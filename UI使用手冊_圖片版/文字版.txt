# SkinDetect UI 使用手冊

更新日期：2026-10-13。適用於專案目前的本機 UI。

## 1. 啟動與關閉

在專案根目錄 C:\Users\User\Desktop\test\SkinDetect 開啟 PowerShell，執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\start_ui.ps1"
```

瀏覽器會開啟 http://127.0.0.1:8765/prototype/skin-detect?variant=A 。保留啟動視窗，關閉視窗或按 Ctrl+C 會停止 UI 服務。

若 UI 是由助理以背景程序啟動，沒有可見終端，可先查詢服務程序，再確認命令列指向此專案的 ui_prototype/server.py：

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen | Select-Object OwningProcess
Get-CimInstance Win32_Process -Filter "ProcessId=查到的PID" | Select-Object ProcessId, CommandLine
```

確認後用 Stop-Process -Id 查到的PID 關閉該 UI 程序。請將「查到的PID」替換為實際數字；若更換埠號，查詢時也需替換 LocalPort。

只啟動服務、不自動開啟瀏覽器：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\start_ui.ps1" -NoOpen
```

只檢查執行環境，不啟動服務：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\start_ui.ps1" -CheckOnly
```

GPU 記憶體不足時，可在關閉 UI 後改用 CPU 啟動：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\start_ui.ps1" -Device cpu
```

埠號已使用時，改用 9000，並連到 http://127.0.0.1:9000 ：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\start_ui.ps1" -Port 9000
```

## 2. 畫面導覽

- 影像推論：選擇疾病模型、上傳照片、執行預測與查看熱力圖。
- 模型訓練：既有的三來源、七分類訓練控制台；預設收合，點標題展開。
- 實驗紀錄：依階段篩選既有摘要、數據與圖表。
- 使用手冊：以瀏覽器開啟本文件，亦可查看 Markdown 原檔。

原型保留三種版型，底部左右按鈕切換，或在未操作輸入欄位時按鍵盤左右方向鍵。

- A 實驗工作台：設定、圖片、模型輸出並排。
- B 單張檢測流程：依選圖、設定、結果的順序呈現。
- C 研究審查台：紀錄、影像與輸出檢查器並排。

三版共用同一個模型與推論流程。切換版型保留目前圖片、結果、實驗標記、人工部位與選項；重新整理整個網頁會重設未送出的欄位與圖片。

## 3. 單張影像推論

步驟 1：選擇疾病模型。模型按階段分組；找不到權重或執行器不支援的選項會停用。預設遵循模型資產庫的 default_model；若該模型不可用，會選擇第一個可用疾病模型，沒有可用疾病模型時才使用展示模式。

步驟 2：點擊上傳區，或拖放一張 JPG、PNG、WEBP。限制為單張 20 MB、6,400 萬像素。畫面會顯示檔名、影像尺寸與大小；損毀或不支援的檔案會顯示錯誤。

步驟 3：填寫實驗標記，例如 external_hand_01。可選填人工拍攝部位。

步驟 4：依需要勾選 Grad-CAM 或探索性部位輸出。

步驟 5：按「執行推論」。第一次使用模型需要載入權重，通常較慢。等待時不能更換輸入影像與疾病模型，以免結果與圖片混淆。

步驟 6：查看完整機率分布、熱力圖、模型名稱、耗時、裝置與影像資料。更換模型後，上次結果仍保留並標示來源；再次按「執行推論」才會產生新結果。

### 推論欄位的作用

- 疾病模型：決定本次疾病推論使用的權重與結構；不會改變訓練控制台使用的模型。
- 實驗標記：用於辨認本次測試，最多 200 字；未填時記錄為「未命名」。
- 拍攝部位（人工）：只寫入結果紀錄，不作為疾病模型輸入。
- 探索性 DensePose 部位預測：額外執行另一個部位模型，輸出頭部、軀幹、上肢、下肢、手／足機率；不會把這個輸出餵回目前疾病模型。
- Grad-CAM：針對最高機率疾病，計算支援模型的空間特徵熱力圖。MLP 與展示模式不支援。

### 看懂結果

目前 UI 登錄的疾病模型使用七類：日光性角化症／表皮內癌、基底細胞癌、良性角化症樣病灶、皮膚纖維瘤、黑色素細胞痣、血管性病灶、黑色素瘤。

各類分數是 softmax 機率，合計約 100%。例如黑色素細胞痣 90%，只表示模型在既有七類中的偏好，不表示照片有 90% 機率確診為該疾病，也不表示模型對未學習的疾病有辨識能力。目前沒有正常皮膚、未知疾病或拒判類別，因此正常皮膚與其他疾病也可能得到很高的既有類別分數。

耗時包含本次模型載入、影像處理、疾病推論，以及勾選的熱力圖或部位推論。第一次與後續推論的時間不宜直接比較。

裝置 cuda 表示 GPU；cpu 表示 CPU；demo 表示展示模式。展示模式的分數是固定規則產生的假資料，畫面會標示，不能當成實驗結果。

### 熱力圖

- 紅／黃：在此張影像中，對所選類別分數相對影響較大的區域。
- 藍／青：相對影響較小的區域。
- 熱力圖通常會先將每張圖各自標準化，所以不同照片的紅色不能直接比較成絕對關注強度。
- 它不是病灶邊界或確診證據；若聚焦背景、衣物或邊角，應記錄成模型可能依賴非病灶訊息的線索，再安排對照測試。
- 熱力圖失敗時，疾病推論可能仍完成，畫面會顯示原因。無空間卷積特徵的模型不會偽造熱力圖。

## 4. 模型與檔案位置

疾病模型清單來自 模型資產庫/model_registry.json，權重集中在 模型資產庫/models/。UI 僅讀取已登錄且目前執行器支援的模型，不會自動挑選最新訓練權重或升級正式模型。

目前 default_model 為 mixed_convnext；這是登錄檔的預設值，不等於對所有資料來源已驗證最優。新完成的 CP-005 權重與八分類模型並未自動接到此七分類 UI。

目前登錄疾病模型使用各自的影像尺寸與正規化設定；既有標準推論會將圖片縮放到模型所需的正方形尺寸。本次 UI 完善沒有更改各模型的前處理或權重。CP-005 的 letterbox 與 NoiseFilter v2 流程是另一套實驗，不能把兩者當成相同輸入處理。

若需同步既有受支援模型，專案已有下面的同步腳本；它會更新資產庫清單與檔案連結，請在確認要更新時手動執行：

```powershell
& "C:\anaconda3\python.exe" ".\模型資產庫\sync_models.py"
```

同步後重啟 UI，才會重新讀取模型清單。未知架構或新的分類頭需要先完善執行器，不能只把權重丟入資料夾。

## 5. 透過 UI 訓練

目前入口固定執行 資料治理與泛化修復/scripts/train_regularized.py，模型為 ImageNet 初始化的 ConvNeXt-Tiny，輸出七類；使用該流程的 HAM10000、BCN20000、PAD-UFES-20 統一清單。

這個入口沒有接到 CP-005 四來源訓練、ISIC_Archive 擴充或 NoiseFilter v2 多日排程。上方疾病模型選單不會切換訓練架構。

資料閘門的筆數來自既有治理報告，是清理後清單的總筆數，不等於單獨訓練 split 的圖片數。詳細資料由該流程的 unified_manifest_v1.csv 決定。

步驟 1：展開訓練控制台，確認模型、資料與資料閘門。

步驟 2：先選煙霧測試，使用最多 280 張訓練影像、每來源最多 70 張驗證影像。此模式用於檢查流程，不用來報告正式效能。

步驟 3：調整參數並按「開始訓練」。確認視窗會列出流程、輪數與種子；確認後才建立任務。

步驟 4：查看狀態、輪數進度、輸出位置與即時日誌。狀態每 2.5 秒刷新；編輯輸入欄位時保留正在輸入的內容。

步驟 5：完成後，結果保存在 UI訓練任務/任務編號/outputs/regularized_seed種子/。它不會自動替換推論模型。

### 各訓練參數

- 執行模式：煙霧測試限制樣本量；正式模式使用此流程全部合格的訓練與驗證資料，不是整個 Dataset 資料夾的全部圖片。
- 訓練輪數 Epoch：1–100。每輪執行該流程的抽樣與訓練；目前採有放回加權抽樣，全部資料可被抽到，但不保證每張圖片每輪都出現。
- 隨機種子 Seed：0–2147483647，用於控制亂數；比較模型時應對齊種子、資料與設定。
- 批次大小 Batch size：1–64。單次送入 GPU 的圖片數；調高會增加顯示記憶體需求。
- 學習率：0.000001–0.01，控制權重更新步幅。
- 權重衰減：0–0.5，用於限制權重規模。
- 標籤平滑：0–0.4，降低訓練目標對單一類別的極端確定性。
- MixUp 強度：0–1，控制訓練時影像與標籤混合的程度。
- 提早停止耐心值：1–20，選模分數連續未改善達到該輪數時，訓練可提前結束。

進度條按完成輪數估算，並非每個 batch 的精確百分比。任務提前停止仍可能正常完成；以 result.json 的 epochs_completed 與 stopped_early 判讀實際輪數。

「停止目前任務」會終止這個 UI 管理的訓練程序；已寫入的權重與日誌保留，但尚未存檔的當輪進度可能失去。它不能停止從 PowerShell 啟動的 CP-005 排程。關閉瀏覽器不會停止訓練；服務重啟後，既有任務檔案保留，但目前畫面只顯示這次服務管理的任務，不支援接管先前程序或續訓按鈕。

UI 訓練入口只追蹤自己啟動的任務；使用前請確認沒有另外的終端訓練或多日排程正在使用同一張 GPU。

## 6. 推論紀錄與實驗紀錄

本次啟動紀錄會顯示實驗標記、中文最高機率類別、模型、機率、耗時與時間。畫面最多顯示最近 8 筆，API 返回最近 20 筆，伺服器記憶體保留最近 50 筆。關閉 UI 服務後這些紀錄清除。

上傳照片留在瀏覽器記憶體，推論時傳送至本機服務；目前不會自動寫入 Dataset 或用來訓練，也不會自動儲存輸入照片。UI 沒有推論結果匯出按鈕，需要保存時可手動截圖並記錄模型名稱、實驗標記與日期。

階段性實驗紀錄庫讀取 實驗紀錄庫/registry.json，依階段篩選，展開卡片後可開啟曲線圖、Markdown、JSON、CSV 等已有快照。這些是紀錄檔，不是可用於推論的權重。

固定資料夾整理與更新使用既有同步腳本：

```powershell
& "C:\anaconda3\python.exe" ".\實驗紀錄庫\sync_registry.py"
```

更新後重新整理網頁即可讀取紀錄清單；模型清單更新則需要重啟服務。

## 7. 常見問題

### 瀏覽器顯示拒絕連線

確認已啟動 start_ui.ps1，且服務終端沒有退出。預設網址使用 127.0.0.1:8765；若指定其他 Port，要同步修改網址。重新載入後按「重新連線」可再次讀取服務資訊。

### 出現 No module named torch

先以 -CheckOnly 檢查指定的 Python。預設使用 C:\anaconda3\python.exe；其他 Python 或虛擬環境不一定有相同套件。環境確實缺少套件時，在專案根目錄執行：

```powershell
& "C:\anaconda3\python.exe" -m pip install -r ".\requirements.txt"
```

### 模型不能選，或畫面進入展示模式

檢查模型資產庫登錄檔、權重路徑與 runtime_supported。搬移專案時需一併保留模型與其必要程式；不含模型的 UI 壓縮包只能提供介面，不能憑空產生真實模型預測。

### 推論很慢或 GPU 記憶體不足

第一次會載入權重；熱力圖與部位輸出會增加成本。可取消選項或使用 CPU 啟動 UI。並行模型包含兩個 backbone，載入與推論通常更耗資源。

### 正常皮膚被高機率判為疾病

目前是封閉的七分類，缺少正常／未知拒判機制。高機率不能證明圖片屬於已學習疾病，也不能單靠 UI 調整修復資料分布與模型校準問題。

### 熱力圖集中在奇怪位置

記錄原圖、模型、最高機率類別與熱力圖。這可能反映背景、構圖或資料來源線索，也可能受到最後特徵圖解析度限制；需要後續遮擋或跨來源對照驗證。

### 訓練按鈕無法使用

查看控制台的資料閘門與連線錯誤。閘門未通過或腳本缺少時不會啟動；目前入口只支援既有固定流程。不要把「正式訓練」理解為已經接通所有新資料與所有實驗。

### 查看檔案位置

- UI 原始碼：ui_prototype/。
- 疾病模型：模型資產庫/model_registry.json 與模型資產庫/models/。
- 部位模型：重要資產/DensePose_五類部位Backbone_2026-08-24/densepose_true_seed17.pt。
- UI 訓練輸出：UI訓練任務/。
- 實驗快照：實驗紀錄庫/。
- 本手冊：根目錄 UI使用手冊.md；瀏覽器 /manual。
