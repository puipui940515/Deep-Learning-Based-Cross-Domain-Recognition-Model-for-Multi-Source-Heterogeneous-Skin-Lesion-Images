# E113　單張八類混淆矩陣（比照組員那張的樣式）

- 日期：2026-11-10
- 狀態：完成
- 相關：資料與 E106 完全相同，只換單張與樣式；逐類 recall 同 E110／E112 引用值

## 目的
使用者要一張與組員那張樣式相同的混淆矩陣，方便並列。

## 做法
- 資料：R2-REG-LONG_45fb4e79_seed17（ep51）的 val_assess 存檔 logits，n=9,588；數字與 E106 相同，不重跑模型。
- 樣式對齊：只顯示列百分比（對角線＝recall）、Blues 色盤、colorbar 0–100、英文軸標、單一面板。
- 類別順序與對方相同（AKIEC BCC BKL DF NV VASC MEL），我們多出的 SCC 接在最後。

## 結果

| 類別 | n | recall |
|---|---|---|
| AKIEC | 399 | 52.6% |
| BCC | 1,357 | 88.6% |
| BKL | 785 | 66.9% |
| DF | 172 | 51.7% |
| NV | 5,300 | 92.3% |
| VASC | 180 | 71.1% |
| MEL | 1,169 | 70.5% |
| SCC | 226 | 45.1% |

balanced accuracy 0.6736。

與組員那張的錯誤「形狀」對照：

| | 組員 | 我們 |
|---|---|---|
| MEL recall | 56.1%（MEL→NV 26.6%） | 70.5%（MEL→NV 19.8%） |
| DF recall | 57.6%（DF→NV 21.2%） | 51.7%（DF→NV 19.2%） |
| AKIEC recall | 69.6% | 52.6% |

## 推論
- 兩張不可直接比：組員是 n=3,621、7 類、epoch 09；我們是 n=9,588、8 類、epoch 51，測試集也不同。只能對照錯誤的形狀。
- AKIEC 差最多，但有結構性原因：我們多一個 SCC 類在跟它搶——AKIEC 有 6.5% 跑到 SCC，SCC 有 16.4% 跑到 AKIEC，兩邊互吃；組員的七類沒有 SCC。

## 限制
- 單一模型、單一 seed；合併矩陣被 ISIC 主導（分來源判讀見 E106）。
- 組員那張的資料與設定只取自執行紀錄的轉述。
