# E82　事後分析：把 swin_t 加進 ADR-0007 的 C10 集成

- 日期：2026-11-07
- 狀態：完成（不支持加入；事後分析，非事先登記）
- 相關：前置 E81（引出本題）、E36／ADR-0007（C10）；後續 E89（明確不再撈集成組合）

## 目的
**不是事先登記的分析**：事先登記的只有 E80 與 E81。E81 發現「R2＋swin 兩個模型的機率平均」在 val_select 是 0.6948，才回頭問：把 swin_t 加進九個等權的 C10，集成會不會變好？解讀時要記得這個順序。

## 做法
- C10 定義照抄 e36_ensemble_family.py：九個事先登記的 arm（R2、R0_s17、R0_s42、R0-AUG、R0-BAL、R1、R2-REG、S0、S4-D）等權平均，池子建構逐行照搬。
- C10+SWIN = 同樣九個＋swin_t，十個等權。
- 分層配對 bootstrap 2000 次（來源內重抽、共用同一組重抽），與 e36 同一套。val_assess 讀 1 次。

## 結果
C10 重現成功：九個等權 val_assess = 0.6890，與 ADR-0007 的數字完全一致。

| 組合 | val_select | val_assess |
|---|---|---|
| R2 單體 | 0.6845 | 0.6541 |
| SWIN 單體 | 0.6746 | 0.6720 |
| R2+SWIN（兩個） | 0.6948 | 0.6808 |
| C10 九個等權 | 0.6976 | 0.6890 |
| C10+SWIN 十個等權 | 0.7053 | 0.6851 |

| 差值 | val_select | val_assess |
|---|---|---|
| C10+SWIN − C10 | +0.77pp [-0.06, +1.58] 含 0 | -0.39pp [-1.28, +0.52] 含 0 |
| R2+SWIN − R2 | +1.03pp [-0.38, +3.33] 含 0 | +2.68pp [+1.13, +4.08] 不含 0 |
| C10 − R2 | +1.31pp [-0.36, +3.62] 含 0 | +3.49pp [+1.12, +5.66] 不含 0 |

## 推論
- **加 swin 進 C10：兩個切分方向相反，兩個區間都含 0，不支持加。** 0.7053 是當時全專題 val_select 的最高值，但它在 val_assess 上反而比 C10 低——正是 E44 第 4 節那個教訓的形狀，不能拿 0.7053 當成果。
- 便宜的觀察：R2+SWIN 只用兩個模型，就吃下 C10 相對 R2 +3.49pp 裡的 +2.68pp（77%），區間不含 0，推論成本是 C10 的 2/9。但這是事後挑出來的組合，要當結論必須換種子重跑驗證。
- 後來（Day5 後段對照外部文件的比較）紀錄寫明：集成本身有效（C10 − R2 在 val_assess +3.49pp），但「加 Transformer」這一步沒有被證實，「提升來自集成，不是來自異質性」。E89 也明確不再撈集成組合，避免重踩本題的坑。
