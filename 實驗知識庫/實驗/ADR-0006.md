# ADR-0006　排除大部分解釋後，僅存的幾條有數字支撐的線索（SCC 取樣上限、BKL 桶、影像模糊、共享骨幹）

- 日期：2026-11-02（～2026-11-03 追加線索四；實驗索引記 2026-11-03）
- 狀態：進行中（ADR 檔的狀態）。整理者註：依執行紀錄，線索一的 R2-SCC 兩次都沒跑完；線索二發展為細類別訓練 R2-FINE，也停在未完成；線索三未見後續處置；線索四已由 E44 等完成（結論記在 ADR-0007）
- 相關：前置 ADR-0002（SCC 缺陷）、ADR-0004、ADR-0005、E19、E20、E21；線索一 E23／R2-SCC；線索二 E70–E72／R2-FINE；線索四 E28、E32、E44

## 目的
ADR-0004 把模型端介入的上限釘在 10.39pp，ADR-0005 排掉了大部分候選解釋。把剩下「有數字支撐」的線索依「改動成本 ÷ 證據強度」排序，決定先做哪一條。

## 做法
四條線索與當時的處置：
1. SCC 的取樣上限（最便宜）：`scripts/train.py` 加 opt-in 的 `class_floor`，不動 manifest。`audit/e23_class_floor_verify.py` 驗證未啟用時 64,780 個權重逐位元相同。啟動 `R2-SCC`（= R2 + class_floor 0.10，20 epoch，刻意不加 R2-REG 的正則化，只動一個變因）。
2. BKL 桶的異質性：拆桶要動 manifest、改 `manifest_sha256`，使所有既有 run 失去可比性，需要人決定；先做不動 manifest 的診斷。
3. 影像模糊：`lap_var` 只是代理，與「病灶明顯」相關，要先把兩者分開才能行動。
4. 共享骨幹的程度（2026-11-03 追加）：E28 的八個一對多專家同時拿掉共享表徵與共用 softmax，無法歸因；寫成事先登記 E32（S0／S2／S3／S4 四級），先跑 S4。

## 結果
線索一（class_floor = 0.10 的期望效果）：SCC 抽取佔比 3.12% → 10.00%（每張重複 1.200 → 3.841），其餘類別各降約 1.08pp；代價是 ISIC 來源質量 25% → 30.32%。

線索二（限制在 ISIC_Archive_Expanded 一個來源內）：

| BKL 桶內原始診斷 | n | 共錯率 | Wilson 95% | 共錯時被判成 |
|---|---|---|---|---|
| Seborrheic keratosis | 374 | 12.03% | [9.12, 15.72] | MEL / SCC / NV |
| Solar lentigo | 78 | 35.90% | [26.15, 46.97] | AKIEC |
| Lichen planus like keratosis | 59 | 35.59% | [24.60, 48.34] | AKIEC |

線索三：每組隨機 400 張，`lap_var < 15` 的比例 25.00% [21.01, 29.47] vs 11.25% [8.51, 14.72]，不重疊（2.2×）；超出部分約 99 張，佔共錯 14%。

線索四：參數實測（convnext_tiny）只有約 222M、128M、28M 三個真正不同的點，共享 stage2 以前的切點在參數上等於沒共享。

「三條加起來能動多少」：ADR 寫「沒有量過，不要假設可加」。

## 推論
- 線索一的後續：
  - 2026-11-02 E24–E26 之後，助理事先寫下預測「R2-SCC 的 SCC recall 會升、precision 會降、F1 不會顯著改善」，理由是 SCC precision 0.483 已低於 recall 等三條證據；決定讓它跑完但期望值訂低。第一次 run 停在 4/20 epoch，沒有 result.json。
  - 2026-11-04 紀錄依 D2 文件指出：SCC 只存在於四個來源中的一個，多抽同一批圖不會產生跨來源訊號，建議不要重跑，除非先解決來源問題。
  - 2026-11-05 以新身分重跑，2026-11-06 停在 epoch 13（best 0.6546，最差來源每個 epoch 都是 ISIC）；同日為了細類別訓練修改 train.py，這個續跑永久作廢。R2-SCC 沒有完成品。
- 線索二的後續：2026-11-06 E70 量到類別內異質性；E71 設計 14 個細類別再收回 8 類；E72 等價性驗證六項通過；R2-FINE 停在 epoch 16（val_select 0.6799），使用者決定不續跑，沒有 result.json，紀錄註明 0.6799 不得對外引用。
- 線索三：執行紀錄中未見後續處置。
- 線索四：結論寫在 ADR-0007——共享程度的階梯是平的，沒有最佳切點；2×2 的損失對比在 val_assess 上四個區間全含 0。

## 限制
- 線索二的 n 很小（78 與 59），區間寬。
- 線索三的 `lap_var` 是代理指標，未與病灶顯著度分開。
- class_floor 會打破來源等質量，而選定指標懲罰來源不平衡，可能反而變差（ADR 自己寫的失敗方式）。
