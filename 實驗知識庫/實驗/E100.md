# E100　同一張圖掛到不同標籤？以影像內容獨立檢查重複影像

- 日期：2026-11-09
- 狀態：完成；其 64-bit dHash 命中大多為假陽性，必須搭配 E100b 解讀
- 相關：前置 E88（位元組雜湊去重的盲點）；後續 E100b（驗證 dHash 命中）、E101（去重 manifest）

## 目的
使用者提出「ISIC 會不會有同圖不同標籤」。manifest 自己標 duplicate_status=unique_after_v2_audit、leakage_status=passed_v2_content_and_group_audit（ISIC 全部 63,998 列），那是聲稱，本實驗獨立驗證。E88 已顯示位元組雜湊去重抓不到「像素相同但編碼不同」的影像。

## 做法
- manifest 層級八項檢查（即時可算）：ISIC 的 record_id／image_id／image_path 重複、同檔名多路徑、同 lesion_id 不同標籤、HAM 與 ISIC 共用 lesion_id 的標籤一致性、跨來源 image_id 碰撞、HAM 與 ISIC 的 id 交集。
- 內容層級，掃全部四個來源 86,534 張（HAM 影像本來就在 ISIC Archive 裡，跨來源重複同時是標籤衝突與洩漏的來源）：
  1. 逐位元相同：先用檔案大小前篩，撞到的才算 sha256。
  2. 視覺相同但位元不同（重新編碼、縮放）：dHash 64-bit；dHash 相同的再比 sha256。
- 只讀影像檔，不動 manifest；用 4 個行程，不跟訓練搶滿 CPU。

## 結果
manifest 層級：

| 檢查 | 結果 |
|---|---|
| ISIC record_id／image_id／image_path 重複、同檔名多路徑 | 皆 0 |
| ISIC 同 lesion_id 不同標籤 | 1 |
| HAM 與 ISIC 共用 lesion_id | 726，其中標籤不一致 0 |
| 跨來源 image_id 碰撞 | 0 |
| HAM 的 8,511 個 id 與 ISIC 的 63,998 個 id 交集 | 0 |

內容層級（讀取失敗 0）：

| 類型 | 組數 | 影像數 | 標籤不一致 | 跨來源 | 跨 split |
|---|---|---|---|---|---|
| 逐位元相同（sha256） | 0 | 0 | 0 | 0 | 0 |
| dHash 64-bit 相同 | 2,397 | 5,423 | 469 | 1,206 | 850 |

## 推論
- 唯一一筆「同 lesion_id 不同標籤」細看後是 **lesion_id 標錯，不是標籤標錯**：同一位病人、同部位的兩張，年齡差 5 歲（兩次不同就診的兩顆病灶），兩張都是組織病理確診，且同在 val_select、同一 group，沒有造成跨切分洩漏；不需要修，但報告要揭露 ISIC 的 lesion_id 不完全可信。
- HAM 與 ISIC 的 id 交集為 0，代表建 ISIC_Archive_Expanded 時已按 image_id 排除 HAM 那批。
- **助理沒有直接回報那 469 組「同圖不同標籤」**：sha256 一組都沒抓到卻有 469 組，而且有群組同時掛 BCC+MEL+NV 三個標籤，同一張影像不可能是這三者。懷疑 8×8 dHash 對皮膚鏡影像太弱（淺色背景上一團圓形病灶，縮到 8×8 彼此幾乎一樣）。驗證見 E100b：絕大多數 dHash 命中是假陽性，但其中確實有 1,682 對真重複。
- 第一版只存了 200 組（只存標籤衝突或跨 split 的），後來改成輸出全部 2,397 組重掃，才讓 E100b 能驗證全部群組。

## 限制
- 64-bit dHash 對這類影像辨識力不足，命中數不能直接當重複數。
- 後來（2026-11-16）的資料盤點指出：manifest 的 duplicate_status／leakage_status 欄位仍全是通過，去重 manifest 未採用。
- 封存測試集未使用；manifest 未修改。
