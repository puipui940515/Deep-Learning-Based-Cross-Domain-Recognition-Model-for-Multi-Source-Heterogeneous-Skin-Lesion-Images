# E144　GPU 時間在各類核心的分布：矩陣乘法佔多少？

## 目的
E138 顯示訓練瓶頸在 GPU 計算。使用者問最新的快速矩陣乘法演算法（Strassen 類）能否應用。助理查文獻後指出：GPU 上一層 Strassen 在 V100 FP32 最多 1.11 倍、交叉點 1,536，而 convnext_small@384、batch 8 的矩陣維度多在交叉點以下；且 E138 的「計算」包含非矩陣乘法的核心，矩陣乘法佔多少還沒量（執行紀錄 Day5 2026-11-16 08:21）。所以先量核心時間分布再決定。

## 做法
- 腳本 `e144_gpu_kernel_profile.py`：與 train.py 相同的訓練步——convnext_small、384、batch 8、autocast FP16、AdamW（layer decay 參數組）、GradScaler、clip_grad_norm 1、cuDNN deterministic、benchmark 關。
- 輸入用隨機張量（核心種類與時間不受影像內容影響）；暖機 15 步，torch.profiler 記錄 30 步，CUDA 核心依名稱歸類加總。
- 歸類修正：卷積類必須排在 GEMM 前，否則 cuDNN 的隱式 GEMM 卷積會被算成矩陣乘法。
- 不訓練、不存權重、不讀資料集；GPU 上有其他 python 就拒絕。RTX 4060、torch 2.11.0+cu128。

## 結果
每步 GPU 時間 124.5 ms。各類佔比：

| 類別 | 佔比 |
|---|---|
| 矩陣乘法（GEMM） | 32.7% |
| 激活與逐元素 | 30.5% |
| 最佳化器（AdamW 等） | 16.2% |
| 卷積（cuDNN／深度卷積） | 9.3% |
| 正規化（LayerNorm） | 8.4% |
| 歸約與損失 | 2.7% |
| 其他 | 0.2% |

佔比最高的三個單一核心都是 FP16 GEMM 核心；逐元素類中 GELU 反向傳播核心是最大的一個（完整清單見報告 JSON 的 top_kernels）。

## 推論
- 矩陣乘法只佔每步 GPU 時間的 32.7%；激活與逐元素（30.5%）、最佳化器（16.2%）、卷積（9.3%）、LayerNorm（8.4%）合計也佔很大一部分。P015 標為已完成，P012 加註「GEMM 佔每步 GPU 時間 32.7%（124.5 ms/步）」。
- P012（快速矩陣乘法）在 2026-11-17 01:34 的提案表審核中仍待使用者決定。

## 限制
- 歸類依核心名稱，「其他」與誤歸類要看 top_kernels 確認。
- 隨機輸入、不含資料載入；只量 30 步、單一設定。
- （整理者註）與 E138 的每步 GPU 計算時間（116.0 ms）量法不同（E138 用真實資料、FDA 設定與插樁），兩者不宜直接比較。
