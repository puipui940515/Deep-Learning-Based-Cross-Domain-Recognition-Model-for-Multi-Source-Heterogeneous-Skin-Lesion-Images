# E45c　draft 最佳化把選定指標移動了多少，以及它橫切在哪兩群 run 之間

- 日期：2026-11-04
- 狀態：完成；更正 E45b 的普查與「640／768 不縮」的說法
- 相關：前置 E45、E45b；引用 E46（BCN20000 是交付形態的地板之一）；影響 ADR 0007 架構表、E34、E22 清冊 9.6

## 目的
E45b 證實 R0 對不上的原因是 draft。E45c 問嚴重度：
1. 開／關 draft，R0 的選定指標與逐來源分數差多少（BCN20000 最重要，因為它是交付形態的地板）。
2. draft 到底縮了誰——改用分層抽樣普查。
3. 釘出 draft 加入的時間，判斷哪些 run 在界線兩側。

## 做法
- 拿 R0 同一份 best.pt，同時跑 draft 開與關兩種前處理，兩個切分都算；val_assess 讀 1 次。
- 分層普查：三個 draft_size（448／640／768）× 四個來源各抽 40 張；尺寸沒變的影像逐像素比對。
- 時間線：依 Day4 執行紀錄的 `[01:4x]` 條目與各 run 的 npz 寫檔時間。

## 結果
R0 兩種前處理：

| 來源 | val_select 開 | val_select 關 | val_assess 開 | val_assess 關 |
|---|---|---|---|---|
| BCN20000 | 0.6775 | 0.6665 | 0.6558 | 0.6523 |
| HAM10000 | 0.7894 | 0.7894 | 0.7870 | 0.7870 |
| ISIC_Archive_Expanded | 0.6665 | 0.6679 | 0.6710 | 0.6691 |
| PAD-UFES-20 | 0.8144 | 0.8144 | 0.8480 | 0.8480 |
| **選定指標** | 0.6665 | 0.6665 | 0.6558 | 0.6523 |

- val_select 差 +0.01pp（地板從 ISIC 換成 BCN），翻 65 張（BCN 1.75%、ISIC 0.42%、HAM／PAD 0%）。
- val_assess 差 +0.35pp（地板都是 BCN），翻 71 張（BCN 1.85%、ISIC 0.63%）。

## 推論
- 影響實際很小，遠低於 1.68–3.69pp 的種子噪音帶；但 draft 開著反而讓 BCN 好 +0.35～1.10pp，沒有解釋也沒有追，因為不影響現有判決。
- 界線主要切在 224 的 run 上（BCN20000 是 1024²，只有 448 這檔會砍半），但不只切在那裡：ISIC 在每一檔都有三到四成被縮。助理先前寫「640／768 不縮」是過度簡化，已修 e45c 註解、E22 9.6、archive/README。
- 2×2 與 E44 階梯全在 draft 後，內部一致；跨界線的是 ADR 0007 表上的「S0 < R0」與 E34 的 S4 − R0。
- 要不要保留 draft 列為待人決定的取捨（讀取吞吐 155.5 → 308.8 img/s 對 BCN 在 224 下只用一半解析度）。

## 限制
- 每來源只抽 40 張。
- 只量 R0 一個模型的嚴重度。
- （整理者註）執行紀錄 10:03 記的第一次分層普查在 448 下 ISIC 是 22/40（`E45_draft_census_tmp.json` 亦同），10:11 的普查與 E45 報告是 31/40；來源沒有說明兩次結果為何不同。
