# E34b　S4 的決策損失是校準問題還是本質問題（事後探索）

- 日期：2026-11-03
- 狀態：完成（事後探索，不是事先登記的分析）；機制解讀後來由 E41 修正
- 相關：前置 E34；同組 E30（組合器 A–C 的來源）；後續 E35、E36（S4-D 進入集成池）、E37、E41

## 目的
E34 量到矛盾：S4 的排序能力（AUC）贏 S0 八類中的七類，決策能力（argmax 選定指標）卻是四個 arm 最差。嫌疑人是逐頭 pos_weight（NV 2.45 到 SCC 47.42）把每個頭推高的幅度不同，使八個頭的原始分數不在同一尺度上。若免訓練校準能把選定指標拉到 R0 的 0.6523 附近，就是校準問題，不是結構問題。

## 做法
- 把 E30 的三種免訓練校準套到 S4，再新增 D；門檻／映射一律在 val_select 上決定，報 val_assess：
  - A 原始分數直接 argmax（E34 用的，對照）
  - B 減掉各自 Youden 門檻後 argmax
  - C 轉成 val_select 百分位後 argmax
  - D 轉成 logit 再減 log(pos_weight)：`BCEWithLogitsLoss(pos_weight=w)` 等價於在 logit 上加 log(w)，扣回去有理論依據
- 依 val_select 挑最好的組合器，與 R0 做分層配對 bootstrap。

## 結果
各頭 pos_weight：AKIEC 6.13、BCC 4.07、BKL 6.19、DF 30.39、NV 2.45、VASC 31.02、MEL 5.65、SCC 47.42（JSON 數值截取至小數第二位）。

## 推論
- 當時結論：S4 的決策損失主要是校準問題。D 在 val_select 上也是四者第一（不是挑 val_assess 好看的），校準後 S4 與 R0 的選定指標分不出高低；pos_weight 最大的 SCC、DF 在原始 argmax 下被過度預測（精確率 18.49%、42.05%），校準後回到合理水準。
- 百分位校準 C 崩掉；E36 的「排名平均」與 E37 的百分位校準撞到同一個失效模式：逐欄排名／百分位把 argmax 需要的列內結構洗掉了。
- 後來 E37 顯示：這個免費的減法（S4-D 0.6526）追平了 3 倍計算量加選檢查點的 S4F（0.6536）。
- 後來 E41 修正機制：選定指標是跨類別 macro，最佳操作點靠近平衡點而不是自然先驗，所以 −log(pos_weight) 的作用是「把過度平衡的 S4 往回拉」，不是「校準到真實先驗」；E41 也確認 S0 的低分不是校準假象。
- E36 結果報告第 3.4 節界定範圍：歷史上的 R0／R1／R2／R2-REG 都是 softmax 模型，不適用這個校準；真正用 sigmoid 頭的只有 S4／S4F 與 S0。

## 限制
- 事後探索：D 的想法是看到 E34 第 3 節的矛盾之後才有的，用 val_select 挑組合器可以減輕但無法完全排除偏差；要乾淨證實應在新種子上事先宣告用 D。
- 單一種子；與 R0 的比較另有 E34 列出的預算與檢查點不對齊問題。
