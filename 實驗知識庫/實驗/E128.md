## 目的
E127 為短跑加入三個 opt-in 功能，改動 `scripts/train.py` 與 `src/augment.py`。要確認：(1) 沒用到新功能的既有 run 行為完全不變；(2) 三個新功能確實照設計作用、且只作用在訓練集。

## 做法
在兩份訓練 router 快照上各開獨立行程跑「探針」再比較（CPU，不碰 GPU，不建立 run）：舊快照 a2855453（即時程式，train.py d5c52c4f），新快照 3c9ff1d2（暫存版 v2）。判準：
1. 既有每個 run × 種子：兩版 cfg 完全相同（在 `revision()` 處攔下）。
2. 預設路徑的資料前處理逐位元相同（同影像、同 torch 種子，訓練與驗證 transform 輸出雜湊相同）；新功能 run 的驗證 transform 與預設相同、訓練 transform 有變化。
3. 還原：新 train.py 拿掉所有 opt-in 標記段 = 舊檔逐位元；新 augment.py 開頭 = 舊檔逐位元。
4. 22k 權重：timm 原模型與轉進 torchvision 的模型 1000 類輸出一致；分類頭以外參數全部來自 22k 檔；8 類分類頭與基準 run 同種子逐位元相同。
5. 低頻互換：視窗內振幅符合 (1−λ)原圖 + λ參考，只作用在訓練集。
6. 隨機外框：作用比例接近設定值；中心半徑 0.75 的圓內從不被蓋到。
另存 `E128_擴充範例.png` 供目視。

## 結果

| 判準 | 結果 |
|---|---|
| 1 既有 run×種子 cfg | 96 組全同（15 組兩版被同一關卡擋下） |
| 2 transform | 預設路徑訓練與驗證逐位元相同；FDA／FRAME 驗證 transform 與預設相同、訓練 transform 有作用 |
| 3 還原 | train 拿掉標記段 = 舊檔；augment 開頭 = 舊檔 |
| 4 22k 轉換 | 1000 類輸出最大差 0.0；342 個骨幹張量全部來自 22k 檔；分類頭與基準逐位元相同 |
| 5 低頻混合 | 視窗內相對誤差 0.0011；λ 落在 [0,1]；視窗外中位數相對變化 0.0002 |
| 6 外框 | 2,000 次中作用 50.35%；中心圓被蓋到 0 次；覆蓋面積中位數 11.7%、90 百分位 29.6% |

暫存版 train.py sha256 784ee51d…、augment.py 046dc3a5…；HC 完成後套用，即時程式 code_sha256 = 3c9ff1d2c599026f（= 驗證過的快照）。

## 推論
- 三個功能都是真正的 opt-in，可以開短跑。
- 重要發現：**舊程式會靜默忽略 fda_prob／frame_prob**，所以 FDA 與 FRAME run 必須在套用新程式後才能開，否則會跑成基準而不報錯。
- 第一版範例圖顯示原論文式 FDA 設定會造出假的深色團塊與大片色斑，因此做了 E129 並修改 FDA 設定。

## 限制
- 驗證在 CPU 上做，屬程式正確性檢查，不涉及任何成績。
- （整理者註）腳本 docstring 寫的新快照是 dea2872f（暫存版 v1，FDA 舊設定），報告與執行紀錄記錄實際比對的是 3c9ff1d2（v2）。
