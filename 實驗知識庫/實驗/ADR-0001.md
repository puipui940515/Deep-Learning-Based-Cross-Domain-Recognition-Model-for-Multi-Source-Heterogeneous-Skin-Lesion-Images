# ADR-0001　選模指標定為 worst_source_macro_f1_ge30（各來源 macro-F1 取最差，只計張數 ≥30 的類別）

- 日期：2026-11-02（ADR 檔寫「CP-005 開始時，2026-11-02 補記」）
- 狀態：完成（已定案）
- 相關：前置 D1／R1 時期的指標演進（worst_source_balanced_accuracy → _ge30 → macro_f1_ge30）；被 E12、E16、E22 用來重算舊 run；ADR-0007 的判準沿用本指標；E41 補充「最佳操作點靠近平衡點」；E116 量到本指標的代價

## 目的
四個來源與八個類別都極不平均，而驗證集是原始分布、沒有重新加權。要決定「用哪一個數字挑 checkpoint、比較 run」，而且這個數字要反映「跨來源都站得住」這個研究目標。

## 做法
- 指標定義：逐來源算 macro F1，取最差的那個來源；每個來源內只平均支撐數 ≥ 30 的類別（`MIN_SUPPORT = 30`）。
- 在 val_select 上選模；val_assess 只用來報告。
- 演進經過（執行紀錄 Day4）：
  1. 最早 R0 家族用 `worst_source_balanced_accuracy`。2026-10-31 22:15 發現這個指標在小格子上跳動，造成提前中止：限制在 ≥30 張的類別重算後，一半的 run 最佳輪往後移（例如 baseline_seed42 第 3 → 第 7 輪）。
  2. 2026-10-31 22:40 在 `metrics.py` 加入 `MIN_SUPPORT=30` 與 `_ge30` 版本，選模改用 `worst_source_balanced_accuracy_ge30`（R1 用這個）。
  3. 2026-11-01 01:4x 使用者指示「精確與召回都看」，選模改為 `worst_source_macro_f1_ge30`（R2 起使用）。
  4. 2026-11-02 寫成 ADR。

## 結果
ADR 列出的理由與數字：

| 理由 | 依據 |
|---|---|
| 不用準確率 | NV 佔驗證集 55%；訓練時取樣器把 NV 壓到 15.27%，目標不對齊 |
| 取最差來源而非平均 | 平均會讓 ISIC 的好成績蓋掉 BCN 的差成績 |
| `ge30` 門檻 | 小類在某些來源只有個位數張，F1 在 0 與 1 之間亂跳 |

背景分布：ISIC 75.3%、PAD 1.9%；NV 57.2%、VASC 0.58%。

本指標與準確率可以反向移動，ADR 舉的例子：R2 → R2-REG，選定指標 +1.30pp，準確率 −0.44pp。

## 推論
- 早期 run（R0、R0-BAL、R0-AUG）的 `result.json` 沒有 `ge30` 欄位，跨 run 比較必須從每個 epoch 存下的混淆矩陣重算，不能直接讀 `result.json`（`audit/e16_curves.py`、`e22_registry.py` 都這樣做）。
- 後來的補充：
  - ADR-0007 引用 E41 的通則：本指標是跨類別 macro，最佳操作點靠近類別平衡點而不是自然先驗，「校準到真實先驗」對這個指標是錯的指令。
  - 事件記憶記載 E116：R2-REG-LONG 的 val_select pooled balanced accuracy 在 ep10 最高 0.7253，選模挑的 ep51 是 0.6960；本指標是 minimax（保最差來源），代價約 3.5pp 的 pooled BA，先前沒有文件記載。
  - 事件記憶另記：主指標可取得的 run 是 38/47，其中只有 4 個綁現行 manifest，34 個綁舊 manifest，兩組 val_assess 張數不同（9,588 對 9,652），跨組不可比。

## 限制
- 指標定義演進過，R0 家族是用舊指標早停的，它們的 best.pt 不是用本指標選的（E12／E16 的修正附錄）。
- 本指標會獎勵小類與弱來源，與整體準確率、pooled BA 可以反向移動，報告時要並陳。
