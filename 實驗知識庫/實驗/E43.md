# E43　預算截斷：是真的，但只有 R1 真的被害到

- 日期：2026-11-04
- 狀態：完成；「R1 應重跑」的建議後來執行了，但重跑後截斷仍在、成績沒有改善
- 相關：前置 E37（預算＋選檢查點 +4.23／+2.09pp）、ADR 0007 架構表、SD-006（R1 檢查點用舊指標選）；後續 E45（draft 對 R1 的影響）、R1 重跑（R1_279af57b_seed17）、E50

## 目的
E37 量到給 S4／M4 加預算＋選檢查點值 +4.23pp／+2.09pp，比 ADR 0007 表上多數架構端介入的效果還大。所以要回頭問：那張表裡互相比較的 arm，預算有沒有對齊？有沒有 arm 是還在進步時就被預算砍斷？

## 做法
- 只讀既有 run 的 `history`（每個 epoch 的 val_select 混淆矩陣），不跑推論，**val_assess 讀取 0 次**。
- 對每個 arm：最佳 epoch 是否就是最後一個（是＝被截斷）、末 3 個 epoch 的實測斜率。
- 不外推（「再多跑幾個 epoch 會到多少」需要假設曲線形狀，不給）。
- 補做：用 `ensemble_predict.py --checkpoint last.pt` 端到端跑 R1 的 ep17。

R1 補上檢查點選擇（兩個檢查點都用現在的程式跑）：

|---|---|---|---|

另外從 history 逐 epoch 重算：R1 的 best.pt 是 ep11（用舊指標 worst_source_balanced_accuracy_ge30 挑的），現行指標在 ep11 是 0.6575，ep17 是 0.6694，差 1.19pp。

## 推論
- 預算沒有對齊（12／12／12／17／20／20），六個 arm 裡 4 個在還在進步時被砍斷。
- 但斜率多半很平：R0、R0-BAL、R2 的截斷無害；只有 R1（+0.510pp/ep）真的被害到。R1 同時有「檢查點用舊指標選」的問題，所以 R1 的單獨成績不要引用。
- 兩個帶判決的 arm（R0-AUG 否決、R2-REG 含 0）都在預算用完前就到頂並下滑，ADR 0007 的判決不需要改。
- S4 → S4F 的 +4.23pp 不能推廣到 R\* 系列：等自由度下只剩 +0.58pp 含 0，而且 S4 根本沒選檢查點、R\* 全部有選。
- 補做的 R1 ep17：val_select +1.12pp 與 history 的 +1.19pp 吻合，但 val_assess 只 +0.31pp，在噪音帶內——修掉的是合規性，不是分數。
- 後來的發展（執行紀錄 16:19）：R1 以現行 config 重跑（R1_279af57b_seed17，20 epoch），最佳 epoch 又是 20/20、末段仍在升（ep18 0.6672、ep19 0.6673、ep20 0.6727），預算截斷沒有被修掉；val_assess 0.6664，比舊 ep11 低 0.47pp、比 ep17 低 0.78pp，三者都在噪音帶內，R1 的名次本來就被噪音支配。
- 後來 E45 指出：R1 ep17 端到端 0.6705 與 history 的 0.6694 差 0.11pp，來自 draft（history 是 draft 前算的）。

## 限制
- 只看 val_select 的 history；斜率只取末 3 個 epoch。
- 不外推，所以無法回答「對齊預算後名次會不會變」。
- R1 的兩個問題疊在同一個 arm，無法分開歸因。
