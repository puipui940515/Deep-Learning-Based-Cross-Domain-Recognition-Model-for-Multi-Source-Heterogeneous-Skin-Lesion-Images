# E57　PAD-UFES-20 墨圈的顏色篩選器（便宜但未驗證）

- 日期：2026-11-05
- 狀態：不採用（未驗證的篩選器；E58 驗出召回率只有 0.265，由 E58 的 Codex 逐張標記取代）
- 相關：前置 E11／E11b／E11c（PAD 墨跡率）、E56（PAD 在偵測裁切下退步）；後續 E58、E58b、E59

## 目的
E56 發現 PAD-UFES-20 是唯一在兩個切分都因偵測裁切退步的來源（val_select −2.48pp、val_assess −2.66pp）；E11 量過 PAD 的醫師墨跡率 15.6%，E11c 以 n=120 收窄到 11.7%（CI 7.1–18.6%）。墨圈是已知風險，但從沒驗證過它真的影響模型行為。要接起來需要每一張 PAD 影像的墨圈標記，而 834 張無法手標，所以先做一個便宜的顏色篩選。

## 做法
- 範圍：PAD-UFES-20 在 val_select（613 張）與 val_assess（221 張）共 834 張。
- 醫師的墨是藍／紫，色相與膚色（橙紅）分得開：縮圖到 256，轉 HSV，數色相 0.50–0.88、飽和度 ≥ 0.25、明度 ≥ 0.12 的像素佔比，≥ 0.1% 就標「有墨」。
- 純 numpy，834 張幾秒鐘；只讀影像，不訓練、不碰 GPU；val_assess 讀 0 次（只產生標記、不算成績）。
- 原計畫第 2 步：分層抽樣送 Codex 驗精確率／召回率；第 3 步：用驗過的標記比較 R2 與 R2-DET（後來分別成為 E58、E59）。

## 結果
| 範圍 | n | 標為有墨 |
|---|---|---|
| 全部 | 834 | 96（11.5%） |
| val_select | 613 | 69 |
| val_assess | 221 | 27 |

墨像素佔比分位數（p50／p75／p90／p95／p99）：0.0／0.0／0.001334／0.007618／0.095343。

## 推論
- 11.5% 與 E11c 人眼 n=120 的 11.7% 幾乎一樣，**但那只是總量吻合，不代表逐張吻合**（把 A 張誤標、又漏掉 B 張，只要 A≈B 總量就會很準），所以篩選器標為「未驗證」，不能直接用。
- 後來 E58 用 Codex 逐張標完 834 張：篩選器精確率 0.75、**召回率 0.265**。E58b 抽查確認淡紫色筆跡畫在皮膚上會去飽和，掉出門檻；深色痣、藍色布單、畫面邊緣的筆桿則會觸發誤報。

## 限制
- 腳本本身明寫「未驗證」：精確率／召回率必須另外驗過才能用。
- E58b 抽查指出：淡紫細線畫在皮膚上會去飽和，掉出設定的門檻而漏標。

## 前因與後果

**前因**
- 引發｜[E11](E11.md)（PAD-UFES-20 的偵測裁切風險：多病灶、醫師墨圈）：E11 的墨跡風險結合 PAD 退步，促成 E57 產逐張標記。
- 引發｜[E11c](E11c.md)（PAD-UFES-20 隨機抽樣擴大到 120 張，量墨）：因為 E11c 量到墨跡比例而未驗證模型影響，所以 E57 建立逐張篩選。
- 引發｜[E56](E56.md)（R2-DET 對 R2：偵測裁切（k=1.5）到底有沒有）：因為 E56 發現 PAD 裁切後退步，所以 E57 建立墨圈篩選器以供檢驗。
- 推翻或更正｜[E58b](E58b.md)（墨跡標記不一致抽查：顏色篩選器與 Codex 誰對）：E58b 目視確認 E57 漏掉淡紫筆跡，也把非墨跡誤標為墨跡。
- 取代｜[E58](E58.md)（用本機 Codex 逐張標記 PAD-UFES-20 全）：因為 E57 篩選器召回率過低，所以改以 E58 的逐張標記取代。

**後果**
- 引發｜[E59](E59.md)（PAD 的偵測裁切退步不是墨圈造成的（k=1.5））：因為 E57 規劃用驗過的標記比較模型，所以後續形成 E59。
