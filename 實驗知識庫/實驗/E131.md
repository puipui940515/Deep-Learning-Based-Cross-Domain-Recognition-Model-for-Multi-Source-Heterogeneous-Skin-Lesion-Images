## 目的
使用者看到訓練只用約 5.2 GB 顯存，決定「改 16，基準重跑」。要登記與 batch 8 版只差 batch_size 的四個短跑，讓 batch 16 的基準與各方法能重跑對照。

## 做法
- `e131_register_b16_runs.py` 新增四個 run，與對應的 batch 8 版只差 batch_size 8 → 16（梯度累積 4 → 2，有效 batch 仍是 32；腳本內斷言）；batch 8 的四個設定原封不動保留。
- 以 `--check-only` 算出 run_id：R2-HC-S20-B16_a3f07fc4、R2-HC-S20-IN22K-B16_1145b282、R2-HC-S20-FDA-B16_149e4f8d、R2-HC-S20-FRAME-B16_5b274d7d。
- 當時正在跑的 batch 8 基準（R2-HC-S20_619c773a）沒有停，理由是跑完可以和 B16 基準直接量出 batch 本身的影響。
- 背景工作 `after_e130_smoke_b16.sh`：等 E130 報告；若 batch 16 放得進實體顯存，就經 router 對四個 B16 run 各做一次冒煙測試（1 epoch、極小子集）；放不下就停並留紀錄。

## 結果

| 項目 | 結果 |
|---|---|
| 登記 | 四個 B16 run 登記於 config.json |
| E130 判定 | batch 16 放得下（峰值 reserved 5,416 MiB），但訓練吞吐 62.0 vs 64.1 img/s，沒有變快 |
| B16 冒煙 | R2-HC-S20-B16 在評估開始時 exit=1、無 Traceback（83 秒，原因未查）；IN22K-B16、FDA-B16 被中途終止；FRAME-B16 未做 |
| 後續 | 使用者指示「回 batch 8，續跑基準」；B16 線結束 |

## 推論
- batch 16 沒有速度好處，四個 B16 設定仍登記在 config.json 但未使用。
- 之後所有短跑（E132 及後續）都用 batch 8。

## 限制
- R2-HC-S20-B16 冒煙 exit=1 的原因未查（B16 已不採用）。
- 停止冒煙時 TaskStop 只停了外層，背景迴圈與其啟動的 router/train.py 行程需逐一手動終止；`smoke_results` 下留有不完整目錄，未刪。
