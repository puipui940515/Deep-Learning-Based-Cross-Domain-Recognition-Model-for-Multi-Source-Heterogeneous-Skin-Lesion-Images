## 目的

2026-11-04 把 `audit/e22_registry.py` 的兩處讀法改成同時接受兩種 result.json schema：`train.py` 的巢狀 `metrics.val_assess`／`history[i].val_select`，以及 `train_shared.py` 的攤平 `val_assess`／`val_select_worst_source_macro_f1_ge30`。原因是後者會讓整支腳本在新 run 上 KeyError 停掉。依 CONTEXT.md 第 8 節，程式碼改動要有程式化驗證，證明舊 run 的數字沒被動到。

## 做法

- `audit/e22b_registry_equivalence.py`：逐個 run、逐個 epoch 比對舊寫法與新寫法的輸出（`macro_f1_ge30`、`worst_mean` 逐字照 e22_registry.py）；對所有舊 schema 的 run，兩者必須逐位元相同。
- 另用舊讀法去讀新 schema 的 run，確認它確實會失敗（即改動的理由）。

## 結果

json 的判定：「舊 schema 的 run 逐一相同，改動只擴大了可讀的範圍」。執行紀錄另記：第 2 節表的 18 個舊列與改動前的輸出逐字相同（目視比對）。

## 推論

改動等價，只擴大可讀範圍；E22 第 9 節據此增補 SHARED_* 的列。

## 限制

- 驗證時只有 8 個新 schema 的 run；E22 第 9.3 節後來列出更多 SHARED_*（含 seed 42 與 S2／S3），本驗證未涵蓋。
- 只驗證讀法等價，不驗證各 run 結果本身。
