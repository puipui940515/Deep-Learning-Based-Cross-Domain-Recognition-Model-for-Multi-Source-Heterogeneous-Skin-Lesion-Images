# E36c　集成的增益是通則還是運氣（事後探索，不找更高的數字）

- 日期：2026-11-04
- 狀態：完成（事後探索；三個問題都沒有參數要選）
- 相關：前置 E36、E36b；同時段 E38、E39；支撐 `docs/adr/0007-ensembling-is-the-lever.md`

## 目的
E36 與 E36b 都在挑「最好的子集」，而最好的子集必然受選擇過擬合影響（select → assess 落差 +2.1 到 +3.5pp）。E36c 反過來問三個不需要選擇的問題：
1. 全部 36 個兩兩配對裡，有幾個平均起來贏過該配對自己較好的那個成員？若多數都贏，「平均兩個不同的 arm 會比較好」就是通則。
2. 留一成員：C10（九個等權平均）拿掉任一成員後還剩多少增益？
3. 把 R2-REG 整個排除後，配對與平均還贏不贏 R2？（E36b 發現 R2-REG 出現在每個大小的最佳子集裡）

## 做法
- 池子同 E36 九個 arm；全部在 val_assess（9,652 張）上算，val_assess 從未參與任何 arm 的訓練或選檢查點。
- 指標 `worst_source_macro_f1_ge30`；bootstrap 2,000 次。
- 另從配對表按推論成本分組（單位 = 一次 `convnext_tiny@224` 前傳）。

## 結果
單 arm（val_assess）：R2 0.6541、R0_s17 0.6523、R0_s42 0.6154、R0-AUG 0.6091、R0-BAL 0.6472、R1 0.6711、R2-REG 0.6671、S0 0.6408、S4-D 0.6526。

| 問題 | 結果 |
|---|---|
| 36 個配對贏過自己較好的成員 | 29／36（中位數 +0.81pp） |
| 36 個配對贏過 R2 | 32／36（中位數 +1.45pp，範圍 −1.52 到 +3.17） |
| 留一成員後九種「八個平均」 | 落在 [0.6762, 0.6833]，對 R2 最小增益 +2.22pp |
| 排除 R2-REG 的八個平均 | +2.92pp，CI [+0.47, +5.24] 不含 0 |
| 不含 R2-REG 的 28 個配對 | 23 個贏過自己較好的成員、24 個贏過 R2 |

留一成員：拿掉 R1 損失最大（−1.28pp），拿掉 R2-REG 損失最小（−0.57pp）。

Bootstrap：C10 +3.49pp [+1.12, +5.66]；無 R2-REG 八個 +2.92pp [+0.47, +5.24]；R2 + R0-BAL 配對 +3.17pp [+0.74, +4.69]，三個都不含 0。

按成本分組（36 個配對）：

| 成本上限 | 配對數 | 贏過 R2 | 最高 val_assess |
|---|---|---|---|
| ≤ 2.01（兩個 tiny@224，R2 的 35%） | 10 | 8 | 0.6712 |
| ≤ 3.05（R2 的 53%） | 15 | 13 | 0.6769 |

例：R0_s17 + R0-AUG 成本 2.00、0.6712、對 R2 +1.71pp；R0-AUG + R1 成本 3.04、0.6769、對 R2 +2.28pp。

## 推論
- 「平均兩個不同的 arm 會比較好」是通則，不是挑到的。輸的七個配對全是弱 arm 互相配對（R0_s42、R0-AUG、S0 之間）。實用規則：平均兩個 arm，其中至少一個要是像樣的。
- 增益不依賴任何單一成員；R2-REG 雖然出現在 E36b 每個大小的最佳子集裡，卻不是關鍵成員。
- 不需要最貴的模型：兩個便宜的 tiny 平均起來就打贏 R2，成本只要約三分之一。
- 分寸：R2 + R0-BAL（0.6858）比 val_select 挑的 R0_s17 + R2-REG（0.6838）好，但那是在報告用的分割上看出來的，不能當成選出來的；可以引用的是分布（32／36 正向、中位數 +1.45pp），不是單一對的名次。
- R0-AUG 單獨是池子裡最差的（0.6091、曾被否決），卻出現在兩個便宜的好配對裡。
- 這些寫進 ADR-0007（暫定）；之後 E39 的成本效益圖在 52 個點裡找到 14 個「比 R2 又便宜又好」。

## 限制
- 事後探索；全部數字都在 val_assess 上看，雖無參數選擇，仍受分岔路徑影響（E40）。
- 本專題沒有真正沒被看過的集合可以確認。
- 成本是 FLOPs 代理，不是實測延遲；池子成員多為單一種子。
