# ADR-0005　「七個模型為什麼錯在同一批影像上」已被排除的解釋清單

- 日期：2026-11-02（～2026-11-04，兩次修正；實驗索引記 2026-11-04）
- 狀態：完成（已定案；2026-11-02 依 E27、2026-11-04 依 E38 各修正一列）。整理者註：其中「資料洩漏」「重複影像」兩列後來被 E100／E100b 與 2026-11-08 的跨來源病灶稽核部分推翻，ADR 檔本身未更新
- 相關：前置 E17、E19、E21；修正來源 E27、E38；與 ADR-0004、ADR-0006、ADR-0007 互相引用；後續推翻 E100、E100b

## 目的
ADR-0004 確立「錯誤是系統性的」之後，逐一檢查候選解釋。把查過不成立的寫下來，要求「重新提出需要新證據，不是新論點」，避免之後再走一次同一條路。

## 做法
- 共錯集在 val_assess 上定義（E17 六模型 760 張；E19 七模型 718 張）。
- 每個候選解釋用 manifest 欄位、確診方式、影像屬性等，比較共錯組與對照組的比例，看 Wilson 區間是否重疊；並檢查是否與類別共線。

## 結果

| 候選解釋 | 證據 | 當時結論 |
|---|---|---|
| 資料洩漏 | `cp005_group` 橫跨 train 的 val_assess 影像 0 張 | 排除 |
| 重複影像 | `duplicate_status` 全部 `unique_after_v2_audit` | 排除 |
| 標籤太弱 | 「追蹤多次影像無變化」1,029 張共錯 0 張；「單張專家共識」1,212 張共錯 7 張；病理確診反而 11.58% | 排除 |
| `mapping_relation`（family vs exact） | 與類別完全共線；MEL 內 family 12.02% vs exact 12.94%（0.93×，重疊）；DF 全是 exact 卻是共錯率最高的一類（25.00%） | 作廢，是類別效應的重新命名 |
| AKIEC 裡的原位鱗癌比較難 | 同來源內原位鱗癌 23.26% vs 日光性角化症 23.39%，重疊 | 無證據支持 |
| 墨跡／來源指紋 | `ink_frac > 0.01` 9.50% vs 14.75%，重疊且方向相反 | 不是主因 |
| 解析度太低 | `min_side` 中位數兩組都是 1024px；小圖比例 30.0% vs 25.5%，重疊 | 排除 |
| 棄權 | 共錯信心 0.768 > 只有自己錯 0.666 | 救不了 |
| 病灶面積 confound（A1） | E12 修正附錄 | 作廢 |

## 推論
- 原位鱗癌：「切點落在 AK → 原位 → 侵襲這條連續譜中間，可以被測出來；但把切點移到別處不會讓題目變簡單」。「不值得為此動 manifest」的決定不變，理由從「測不到」改成「測得到但沒有收益」。
- 棄權：對「修」仍成立（集成 760 張共錯只修對 1 張），對「避」不成立（可以把 92.4% 的共錯棄掉）。不能把 40% 覆蓋率下的 98.58% 說成「模型有 98.58%」。
- 兩個但書：「標籤太弱被排除」不能反過來說「標籤都是對的」（病理只做在可疑病灶，確診方式與難度共線）；`mapping_relation` 沒用不代表標籤本體沒問題（BKL 拆開後確有問題，見 ADR-0006）。
- 被自己推翻的推薦：family 桶與原位鱗癌都在 E17 後被推薦為「值得動 manifest」，隨後在 E19 被自己的數據推翻。
- 後來的推翻（ADR 檔未更新）：
  - 2026-11-08：manifest 裡有 726 個 lesion_id 同時出現在 HAM10000 與 ISIC_Archive_Expanded，其中 296 個橫跨 train 與 val，`cp005_group` 卻全部不同，所以分組檢查攔不到。影響 val_assess 9,588 張中 211 張（2.20%）；剔除後最差來源不變（BCN 0.6819）。
  - 2026-11-09 E100／E100b：全資料 1,682 對驗證過的同圖重複；148 張 val_assess 影像在 train 有同一張實體影像，模型在它們上面準 14–16pp；扣除後最差來源 0.6819 → 0.6728（−0.92pp，紀錄寫這是下限）。另有 25 對同圖不同標籤，其中 6 對是 NV vs MEL。
  - 所以表上「資料洩漏 0 張」「重複影像排除」兩列，以後來的檢查看並不成立；但紀錄也寫明幅度小於種子噪音帶，不改變既有比較結論。

## 限制
- 原位鱗癌 n=86，區間寬。
- 共錯集是單一種子的 ConvNeXt 家族模型定義的（見 ADR-0004）。
- 「重複」與「洩漏」原本依賴 manifest 自帶的稽核欄位，後來證明該稽核沒有查跨來源 lesion_id，也沒有做內容層級的去重。
