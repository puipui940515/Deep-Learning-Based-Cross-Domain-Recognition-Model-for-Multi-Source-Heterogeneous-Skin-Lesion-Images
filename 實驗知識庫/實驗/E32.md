# E32　共享骨幹階梯：完全共享 vs 部分共享 vs 完全不共享（事先登記的設計）

- 日期：2026-11-03
- 狀態：完成（設計文件；S4 於 E34 執行，S3／S2 於 E36 時段執行，結果見 E44：階梯是平的）；第 4 節取樣條件與第 6 節判讀表第一列各更正一次
- 相關：前置 E28、E29、E30；執行 E34（S4）、E44（S3／S2）；`docs/adr/0006-remaining-leads.md` 線索四

## 目的
使用者提議比較共享骨幹／部分共享／完全不共享。關鍵論點：E28 的八個專家相對 R0／R2 同時拿掉了「共享表徵」與「共用 softmax」兩件事，不管結果往哪邊倒都無法歸因。缺的那一格是「共享骨幹 ＋ 八個獨立二元頭」（有共享表徵、無共用 softmax），一個模型就能分離兩個因素，所以優先跑它。

## 做法
- 參數實測（`convnext_tiny`，純 CPU 計算）：全部 28.59M，stage3 10.817M、stage4 14.289M，參數幾乎全在最後兩個 stage。

| 代號 | 共享 | 私有 | 八支合計參數 |
|---|---|---|---|
| S0 | 無 | 整個骨幹 ×8（即 E28） | 222.57M |
| S2 | `features[:5]`（stem＋stage1＋stage2） | stage3＋stage4 ×8 | 211.86M |
| S3 | `features[:7]`（到 stage3） | stage4 ×8 | 127.87M |
| S4 | 整個骨幹 | 只有八個二元頭 | 27.84M |

- 參數上只有三個真正不同的點（約 222M、128M、28M）；淺層切點等於沒共享，但 `features[:5]` 可以讓「共享低階特徵」單獨變動而容量幾乎不變。參數不等於 FLOPs，秒數要實測。
- 執行順序 S4 → S3 → S2。
- 取樣器：共享骨幹只有一個 batch，八個頭無法各自 50/50。決定先用（甲）一個多類別取樣器 + 逐頭 `BCEWithLogitsLoss(pos_weight = 負例數/正例數)`；（乙）八個子 batch 拼接可控制取樣但計算量八倍，只在（甲）輸掉時才需要。
- 預算對齊：用「每個頭的曝光次數」對齊，即共享版 8 epoch × 32,000 draws（總計算量只有 S0 的八分之一）。其他條件與 E28 一致：tiny@224、seed 17、不選檢查點。
- 判準：主指標 `worst_source_macro_f1_ge30`，決策規則八個頭分數的 argmax；次指標逐類 OVR AUC；「明顯」= bootstrap 95% 區間不重疊；差距落在 1.68–3.69pp 種子噪音帶內一律當沒差。

| 如果看到 | 結論（事先登記） |
|---|---|
| S4 ≥ S0 且 S4 ≈ R0 | 原寫「共用 softmax 在壓抑」，已更正為「拆輸出頭無害，拆骨幹有害」 |
| S4 ≥ S0 但明顯低於 R0 | 兩因素都不是主因，差距來自預算、取樣或單一種子 |
| S4 < S0 | 共享表徵有害，專家化方向對 |
| S3 或 S2 高於兩端 | 最佳切點在中間，值得把階梯做完 |
| 四級都在彼此區間內 | 共享程度不是可操作的槓桿，收掉這條線 |

## 結果
本頁是設計文件，沒有自己的數字結果。執行結果：
- S4（E34）：照原始 argmax 是四個 arm 最差；校準後與 R0 分不出高低（詳見 E34／E34b）。
- S3、S2（E36 時段、E44）：S2／S3／S4 三者在兩個切分上的六個配對區間全部含 0；實測訓練時間 S3 38.7 分、S2 71.8 分、S4 24.9 分。

## 推論
- 2026-11-03 兩處更正（判準本身未動）：
  1. 第 4 節原把取樣條件寫成「與 R2 同條件」。實際 R2 在 config 覆寫 `sample_exponent=1.0`，R0 用 0.5；S4 的對照組是架構相同的 R0，所以取樣用 0.5（e=0.5 時 SCC 2.07%、DF 3.19%；e=1.0 時 SCC 3.12%、DF 10.27%）。
  2. 判讀表第一列的因果標籤寫反：S4 ≈ R0 的意思是拿掉共用 softmax 既無害也無益，不是 softmax 在壓抑。
- 後來 E34 建議先不做 S3／S2（兩端差距只約 1pp，全共享端參數與計算量少 8 倍）；E36 時段仍做完，E44 確認階梯是平的，「最佳切點在中間」的答案是否定的，私有容量不是槓桿。
- 後來（E36 時段）也更正：1.68–3.69pp 噪音帶的出處是 E18／E21，不是 E32。

## 限制
- 不改變 E17 的模型端上限 10.39pp。
- 不回答最終架構該選哪個（最終版本須維持 ≥ 8 類，選定仍走 CP-005 流程與人工閘門）。
- 每級各一顆 seed 17；`sample_exponent`、`class_floor` 等取樣參數固定不動。
- 甲案的取樣分布與 S0 不同，是一個未控制因素。
