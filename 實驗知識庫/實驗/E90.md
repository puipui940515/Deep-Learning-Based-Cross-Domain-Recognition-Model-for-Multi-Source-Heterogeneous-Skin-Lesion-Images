# E90　依使用者指示，把 E88 找到的 68 張純白影像排除出資料切分

- 日期：2026-11-07
- 狀態：完成（manifest 已改；此後 val_assess 分母由 9652 變成 9588）
- 相關：前置 E88；後續 E91（第一個在新分母上判定的 run）、E93（manifest 變動使舊 last.pt 永遠不能續跑）；影響 G-DET 人工閘門（E8）

## 目的
E88 找到 68 張每個像素相同的純白影像（64 張在 val_assess），處置要先問人。使用者 2026-11-07 明確指示「先排除」。這覆寫了先前「不要動 cp005_manifest.csv」的常規，所以本實驗要以不改程式碼、可追溯的方式排除，並把所有連帶後果逐項記下。

## 做法
- **改 `split`，不是改 `training_eligible`**：train.py 只用 `split` 欄篩資料，完全沒讀 `training_eligible` 或 `exclusion_reason`，設那兩欄不會有效果。所以把 68 列的 split 改成 `excluded`，不需改任何程式碼，code_sha256 不變；`training_eligible=False` 與 `exclusion_reason`（保留原本的 split）一併設好當文件。
- 改動前先把 manifest 備份到 `archive/`（檔名含舊 sha 前 16 碼，sha 已驗證與原檔相同）。
- 逐格驗證備份與新檔：形狀 (86534, 46) 一致、欄名一致、record_id 順序一致；差異列 68、差異欄只有 `exclusion_reason`、`split`、`training_eligible`，差異格數 204＝68 列 × 3 欄。
- 同步更新 `reports/cp005_split.json`（manifest_sha256、重算 counts，新增 manifest_sha256_history 保留舊 sha、時間、原因、備份路徑）：train.py 對每個 run 都 assert 這個 sha 要與 manifest 相符，不同步更新的話所有訓練會立刻失敗。這是腳本產生的一致性紀錄，不是人工閘門。
- **刻意不更新**：`reports/E8_detect_bbox_review.json`（G-DET 人工視覺閘門，人於 2026-11-04 核准，腳本不得代為重新核准）、`reports/R0_bbox_stats.json`（G-R0 本來就未核准）、各 run 的 config_snapshot.json／result.json（血統紀錄，約 116 個）。
- 不刪除任何影像檔。

## 結果
- manifest_sha256：`462a5df9…` → `29d29514…`。

| 切分 | 排除前 | 排除後 |
|---|---|---|
| train | 64780 | 64776（-4） |
| val_select | 12102 | 12102（不變） |
| val_assess | 9652 | 9588（-64） |
| excluded | 0 | 68 |

只有 ISIC 變動（train 48750→48746、val_assess 6975→6911）。排除後各來源：BCN20000 8759／1712／1462、HAM10000 6013／1504／994、ISIC_Archive_Expanded 48746／8273／6911、PAD-UFES-20 1258／613／221（train／val_select／val_assess）。

實測後果：
- `--run R2-DET --check-only` 被 train.py 的 G-DET assert 擋下（crop='detect' 的 run 在人重新核准前無法啟動）。
- 所有既有 run 的 run_id 再次失效（2026-11-06 改 models.py 時已失效過一次），`--resume` 接不上任何既有 run；實測的新 run_id 例如 R2-REG 7e6c866c、R2 76276cb0、R1 394912d7、R2-SWIN 0e8a5e41。
- 既有的 `*_logits.npz` 仍含那 64 筆 val_assess 紀錄；之後以 `split=='val_assess'` 篩 manifest 的分析會自動少掉它們，用 reindex 的不會。

## 推論
- **val_select 完全沒變是關鍵**：所有以 val_select 為準的歷史比較（R2-REG 0.6907、R2 0.6845、R2-SWIN 0.6746…）仍然有效，不需重算。只有 val_assess 之後建立在 9588 張上，與舊的 9652 張不直接可比（E91 起明確標註）。
- G-DET 被擋是閘門在正常運作，要恢復必須由人重新看過 bbox 並更新 E8。後來的紀錄（2026-11-16）說明：G-DET 的核准綁在舊 manifest `462a5df9` 上，此後 crop=detect 一直被 manifest_sha256 的 assert 擋住。
- 同一天另一件事：使用者要求挑目前最優設定拉長訓練，R2-REG-LONG（60 epoch）在排除生效後開跑，判定見 E91。

## 限制
- 只排除純白影像；E88 的判準抓不到「有內容但錯誤」的影像。像素內容層級的重複與標籤衝突後來由 E100／E100b 另查。
- 這次排除使既有 run 的 run_id 失效，新舊 run 之間的 val_assess 數字需用共同分母才能比較。
- 封存測試集未使用。
