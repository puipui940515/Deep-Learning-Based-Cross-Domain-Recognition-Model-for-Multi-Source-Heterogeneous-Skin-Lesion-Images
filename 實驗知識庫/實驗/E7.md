# E7　類別無關的病灶分割器（ResNet18-UNet），為偵測裁切產生全資料集的病灶框

- 相關：前置 E6（遮罩覆蓋）；後續 E8（稽核與閘門）、E11（多病灶與墨圈風險）、E53–E55（框大小與裁切放大倍率）、E56／E60（R2-DET 對照）

## 目的
E1 推論模型用了與來源相關的線索（孔徑、病灶佔畫面比例等），D3 提出「偵測 → 緊貼病灶裁切 → 分類」來拿掉這些線索。E7 要訓練一個不分類別的病灶分割器，對全部影像輸出病灶框，供 `crop=detect` 使用。

## 做法
- 腳本 `audit/e7_detector.py`，兩個子命令 train／predict。
- 模型：ResNet18 編碼器加對稱解碼器（UNet18，約 14.3M 參數）；選它是因為專案已有這組權重，不引入新依賴。損失 BCE + Dice；AdamW lr 3e-4、餘弦退火；輸入 256；12 epoch；以偵測器 val 的 Dice 選最佳。
- 協定約束（寫在檔頭）：
  - 只用分類器 train split 的影像訓練與選模；val_select／val_assess 的遮罩完全不參與，留作最後的獨立檢查。
  - 偵測器自己的 train／val 用 `cp005_group` 切（約 1/8 群組當 val），與分類器同一套分組，避免同病灶跨切分。
  - 輸出正規化 xywh（`bbox_norm`），因為 `train.py` 會先做 `Image.draft`，像素座標不安全。
- 出框規則：框是整張遮罩所有非零像素的外接矩形（不是最大連通元件）；遮罩面積小於全圖 0.05% 時 fallback（之後由裁切程式退回中央 0.7 正方形）。

## 結果
偵測器訓練（detector_v1）：

| 項目 | 數值 |
|---|---|
| 輸入 | 8,002 張（有遮罩且屬分類器 train split） |
| 偵測器 train／val | 6,998／1,004 |
| val 來源 | HAM10000 754、ISIC 250（BCN、PAD 各 0） |
| val 類別 | NV 688、MEL 129、BKL 109、BCC 46、AKIEC 18、VASC 8、DF 6 |
| best val Dice | 0.9289（第 11 輪；第 10–12 輪 0.928–0.929） |
| 逐來源 Dice | HAM 0.9405／ISIC 0.8936 |
| 逐類 Dice | VASC 0.9606、DF 0.9576、NV 0.9440、MEL 0.9197、AKIEC 0.9135、BKL 0.9006、BCC 0.7920 |

全資料集出框（`data/bbox_detect.json`，schema skindetect-bbox-v2）：86,534 筆，fallback 1,117 筆（1.29%），原因全部是 mask_too_small。框對遮罩的 IoU 等稽核數字見 E8。

## 推論
- 0.9289 這個總數被 HAM 的 NV 皮膚鏡照主導（val 有 68.5% 是 NV、75% 是 HAM）。BCC 0.792（n=46）是唯一明顯偏低的類別，紀錄要求在稽核拼圖上特別看。
- BCN 與 PAD 在偵測器 val 裡是 0 張，偵測器在那兩個來源的品質仍無法量化驗證，因此要靠 E8 的人工視覺閘門。
- 後來發現「外接整張遮罩」的出框規則會讓框跨越多顆病灶，或被醫師墨線界定（E11）；E53 用 Codex 交叉驗證 BCN／PAD 各 30 張，不一致幾乎都是偵測器「框太大」；E54／E55 量到 k=1.5 時 37.7% 的影像裁切後沒有放大。

## 限制
- 偵測器 val 只含 HAM／ISIC，數字不代表 BCN／PAD。
- 單一訓練、單一設定（size 256、12 epoch），未做其他超參數比較。
