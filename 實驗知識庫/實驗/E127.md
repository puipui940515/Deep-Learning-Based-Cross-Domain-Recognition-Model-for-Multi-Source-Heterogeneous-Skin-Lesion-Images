# E127　登記四個 20 epoch 短跑：基準、ImageNet-22k、低頻頻譜互換、隨機外框

- 日期：2026-11-12
- 狀態：完成（四個 run 登記完成並都跑滿 20 epoch；FDA 的設定在啟動前被 E129 修改）
- 相關：前置 E122（FDA、外框構想）、E123（manifest）、E126（22k 權重）；同批 E128（opt-in 驗證）、E129（FDA 設定修正）；後續 E131（batch 16 版）、E132（短跑對比）、E133（FDA+FRAME）、E136（P29）

## 目的
把 E122 排程的兩個「減弱無關相關性」擴充（低頻頻譜互換、隨機外框）與 E126 選定的 ImageNet-22k 預訓練做成可直接對照的短跑，並各自與同設定的基準比較。使用者規則：測試一律短跑，60 epoch 只給正式長跑。

## 做法
- 程式改動（opt-in，預設路徑不變）：`src/augment.py` 檔尾附加 timm→torchvision 參數名轉換、FDA 頻譜庫、FourierStyleSwap、RandomFrame；`scripts/train.py` 插入四段（import、styled 影像路徑在翻轉後、ColorJitter 前、`__getitem__` 分支、建模後載入預訓練權重）。因 R2-REG-LONG-HC 還在用即時程式訓練，新程式先寫在暫存區，以訓練 router 快照驗證（E128），HC 完成後才套用。
- `e127_register_short_runs.py` 在 config.json 只新增四個 run（既有 32 個 run 未變），全部用 E123 的排除官方測試集 manifest：

| run | 與基準的差異 |
|---|---|
| R2-HC-S20 | 基準：R2-REG-LONG-HC 的設定，epochs 60 → 20 |
| R2-HC-S20-IN22K | + ImageNet-22k 預訓練（timm convnext_small.fb_in22k_ft_in1k_384） |
| R2-HC-S20-FDA | + 低頻頻譜互換，登記時為 fda_prob 0.5、fda_beta 0.01、每來源頻譜庫 256 張 |
| R2-HC-S20-FRAME | + 隨機外框，frame_prob 0.5 |

- 助理自選的設定（使用者未指定）：FDA 套用機率 0.5（比照外框）、每來源頻譜庫 256 張；外框機率 0.5 使用者已同意。
- 同晚 E129 把 FDA 改為 fda_radius 1、fda_lambda_max 1.0（λ~U(0,1) 混合）；該 run 當時從未啟動。
- 冒煙測試（2026-11-13 00:38，1 epoch、極小子集）：四個都 exit=0、有 result.json、日誌 0 個 Traceback；IN22K 印出權重 sha256 並載入 342 個張量。

逐 epoch 比較與 seed 42 複製見 E132。

## 推論
- 四個 run 的對比結論記在 E132：IN22K 明顯較差；FDA 對 PAD 兩個 seed 一致為正、對 ISIC 為負；FRAME 在 seed 17 對 ISIC 的正向訊號在 seed 42 沒有重現。
- 核對：FDA 設定確實在 config_snapshot 的增強區段（fda_prob 0.5、radius 1、lambda_max 1.0），IN22K 的 pretrained_weights 在 run 區段，皆有生效。

## 限制
- 20 epoch 短跑；基準的最後一個 epoch（ep20）仍是最佳。
- 單一 seed（seed 42 後來只複製了基準、FDA、FRAME）；當時記錄的單一 seed 雜訊帶 1.68–3.69pp。
- 冒煙測試的數字無意義，只檢查跑得起來。
