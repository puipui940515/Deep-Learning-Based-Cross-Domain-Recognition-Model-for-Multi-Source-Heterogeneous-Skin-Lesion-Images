## 目的
E120 建好了排除 ISIC 2018 Task 3 測試集（醫師判讀用）的 manifest，但 `train.py` 的 manifest 路徑是全域設定，並綁定 `reports/cp005_split.json` 這份 split gate。要用排除版訓練，必須讓 train.py 能「逐 run 指定 manifest」。這次要回答：加了這個 opt-in 覆寫後，沒用到它的既有 run 行為是否與改之前完全相同，以及排除版 manifest 是否通過自己的 split gate。

## 做法
- `train.py` 新增 opt-in 覆寫：run 設定裡的 `manifest` 與 `split_gate` 兩個鍵（留在 cfg['run']，成為 run 身分的一部分）。改前備份 train.py；code_sha256 由 d81d4efd11ceb333 變為 d5c52c4f39b3eb3f。
- 等價性驗證（`e121_manifest_override_equivalence.py`，不碰 GPU、不建 run 目錄）：把改前與改後的 train.py 各自當模組載入，對 config.json 每個 run × 每顆種子呼叫 main()，在 `revision()` 前攔下 cfg 比較。判準：
  1. 每個沒用覆寫的 run：兩版 cfg 完全相同；若在關卡被擋，例外型別與訊息也相同。
  2. 把新增那段改回去，sha256 等於改之前。
  3. 每個用了覆寫的 run 與其基底 run 只差 manifest／manifest_sha256／兩個新鍵／run_name。
  4. 覆寫了 manifest 卻沒給 split_gate 會被擋下。
- Split gate（`e121_holdout_split_gate.py`，腳本檢查的關卡，不是人工視覺關卡）：替 `cp005_manifest_holdout_isic2018.csv` 產生獨立的 gate，五項檢查；原本的 `reports/cp005_split.json` 不動。同時在 config.json 登記 run R2-REG-LONG-H18（= R2-REG-LONG + manifest 覆寫）。

## 推論
- 覆寫機制是真正的 opt-in：既有 90 組 run×種子的設定不受影響，之後的排除版 run 都可以透過它指定 manifest。
- 代價：train.py 的 code_sha256 改變，已停止的 R2-REG-LONG seed42 若要續跑，必須先把備份的舊 train.py 還原（後來由訓練 router 的快照機制解決）。
- 疏失與更正：啟動 R2-REG-LONG-HC 前重跑本驗證時回報「有判準不通過」，而啟動指令沒有以驗證結果為條件。事後查明是驗證腳本把新加的 HC 當成「既有 run」（改前的 train.py 本來就不認得覆寫），不是 train.py 有變；把「既有 run」改成「沒有用到覆寫的 run」，並讓判準 3 檢查每一個用了覆寫的 run，重跑 90/90 全過。

## 限制
- split gate 是腳本關卡，不是人工視覺關卡。
- 驗證只比較到 `revision()` 之前的 cfg（code_sha256 本來就會因程式改動而變，不在比較範圍）。
