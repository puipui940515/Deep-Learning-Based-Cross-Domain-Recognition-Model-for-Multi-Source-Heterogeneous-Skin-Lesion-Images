# E45b　R0 對不上的真正原因：未提交的 `Image.draft` 改掉了評估前處理

- 日期：2026-11-04
- 狀態：完成（H3 成立）；腳本內的普查與「draft 對 384 惰性」的說法後來被 E45c 修正
- 相關：前置 E42、E45（H1、H2 被打掉）；後續 E45c（嚴重度、分層普查、時間線）

## 目的
E45 排除了 H1（npz 是 last.pt 寫的）與 H2（batch 造成的）。剩下的候選是程式漂移：`git diff` 顯示 `scripts/train.py` 有一行未提交的改動，在 `Images.__getitem__` 加了 `im.draft('RGB',(draft_size,draft_size))`，`draft_size = size*2`。E45b 檢定這個改動（H3）是不是 R0 存檔對不上的原因。

## 做法
- JPEG 的 draft 只能選 1、1/2、1/4、1/8 的縮小倍數。R0 是 size 224 → draft_size 448；R2-REG 是 384 → 768。
- 把 draft_size 設成極大值（等於關掉 draft）重跑 R0 與 R2-REG，看與存檔的差是否歸零。
- 只讀既有存檔與權重，不訓練、不改 `train.py`，val_assess 讀分 0 次。
- 另做一次「draft 縮了哪些影像」的普查。

## 結果

| 成員 | draft 開 | draft 關 |
|---|---|---|
| R0_9af08b24_seed17 | max 1.974e-01、翻 71 張 | max 0.0、翻 0 張 |
| R2-REG_5a8fde80_seed17 | max 0.0、翻 0 張 | max 1.741e-01、翻 24 張 |

- R0 的 npz 寫於 2026-10-26 05:39，draft 是之後才加的，所以 R0 存檔是「沒有 draft」的輸出；R2-REG 存檔是 draft 之後的輸出。
- 這支自己的普查取 manifest 的前 400 列，報出「縮小 0 張」。

## 推論
- H3 成立：兩個成員都能做到完全一致，只是一個要關 draft、一個要開。原因到此結案。
- 腳本 docstring 原本推論「draft 對 R2-REG 是惰性的」（1/2 之後約 500 < 768 所以不縮）；但實測 R2-REG 關掉 draft 會翻 24 張。**後來 E45c 發現**解析度特別高的 ISIC 影像在 768 下仍會被縮，「640／768 不縮」是過度簡化。
- **普查是抽樣錯誤**：前 400 列是 manifest 順序，剛好沒有 BCN20000，所以報出「縮小 0 張」。E45c 改成四個來源各抽 40 張才看到 BCN20000 在 448 下全部被砍半。

## 限制
- 只檢定兩個成員。
- 普查不分層（已由 E45c 更正）。
