# E93　清理權重檔：刪 44 個檔、釋出 15.09 GB

- 日期：2026-11-08
- 狀態：完成（基礎設施；經使用者核准）
- 相關：前置 E90（manifest_sha256 變動）、E92（train.py 改動使 code_sha256 變動），兩者使舊 last.pt 永遠不能續跑

## 目的
使用者 2026-11-08 14:00 要求「幫我清理一下權重檔案留個best與last就好」。但每個 run 目錄本來就只有 best.pt 與 last.pt，字面照做等於什麼都不刪。助理把全 worktree 的 77 個權重檔（19.2 GB）分組列成三個選項，使用者選了第二項「再加全部 last.pt（15.09 GB）」。磁碟 C: 當時只剩約 13 GB。

## 做法
刪除範圍（使用者核准）：
- A　`smoke_results/` 底下全部 best.pt／last.pt（`--smoke` 只跑 1 epoch 的煙霧測試）。
- B　`.torch_home` 快取裡與使用者家目錄 torch 快取**重複**的兩個 ImageNet 權重（convnext_small、swin_t）。查證：真正的 run 用的是家目錄快取；腳本逐檔驗證家目錄確實有同樣大小的一份才刪。
- C　`results/*/last.pt` 全部。

為什麼 last.pt 可以刪：last.pt 只有 `--resume` 會用到，而 train.py 對有 result.json 的 run 直接拒絕 resume（35 個 run 有 result.json）；其餘 5 個沒有 result.json 的 run，config 也已對不上（code_sha256 於 2026-11-08 加 `--init-from` 時變過、manifest_sha256 於 2026-11-07 排除 E88 的 68 張時變過）。這 28 個 last.pt 已經永遠不能 resume。

絕對不刪（腳本內 assert 強制）：
- `results/*/best.pt`——真正的模型權重（「沒有權重的分數不算成績」）。
- `results/detector_v1/best_seg.pt`——產生 bbox_detect.json 的偵測器，G-DET 的來源。
- `.torch_home` 的 MiDaS 與 efficientnet_lite3 權重（家目錄快取沒有，可能被 noisefilter_v2 使用）。
- 正在跑的 R2-REG-RESTART 整個目錄（建清單時就跳過）。
- 任何非權重檔（result.json、progress.json、config_snapshot.json、*_logits.npz）。

流程：先 `--dry-run` 列出 44 個檔與大小，再 `--apply`；事前守衛全部通過。

## 結果
| 組別 | 檔數 | 大小 |
|---|---|---|
| smoke_results | 14 | 3.67 GB |
| .torch_home 重複快取 | 2 | 0.29 GB |
| results 的 last.pt | 28 | 11.13 GB |
| 合計 | 44 | 15.09 GB |

- 權重檔 77 個／19.2 GB → 33 個／4.08 GB（results 31 個＝30 個 best.pt＋best_seg.pt；.torch_home 2 個）。
- 保留 30 個 best.pt，共 3.92 GB。
- 磁碟 C: 可用 13.2 GB → 28.3 GB。
- 刪除期間 R2-REG-RESTART 持續正常執行。

## 推論
- 一個助理自己造成的誤報：刪除本身成功，但腳本最後的「刪完驗證」把 `results/` 底下所有目錄都當成 run 檢查，對三個本來就不是 run 的目錄誤報並 assert 中止——覆蓋圖目錄 OVR、detector_v1（權重檔名是 best_seg.pt）、一個只有 config_snapshot.json 的孤兒目錄 R2-DET_e26673e6_seed17。三者都不在刪除清單裡，已逐一確認內容完整，**沒有任何東西被誤刪**。
- 因為 assert 中止在寫報告之前，`E93_權重清理.json` 是事後由另一支腳本補寫，並在報告裡註明；那道檢查已改成只看真正動過的目錄。

## 限制
- 刪除不可復原；只刪權重，沒有刪任何影像、logits 或 JSON。
- 報告 JSON 為補寫，非刪除腳本當場產出。
- 封存測試集未使用；沒有碰任何人工閘門。
