# SkinDetect Agent 工作規則

## 適用範圍與新專案基準

- 本專案以同學提供的程式碼為基底。先理解本專案現有程式、文件與執行方式，再依使用者當次需求修改。
- 本文件只移植通用工作規則，不代表沿用舊專案的程式、目錄架構、資料配置、模型、實驗設定或成果。
- 舊專案的完成紀錄、測試結果、權重與執行授權，不得視為本專案已完成、已驗證或已獲授權的證據。
- 不因舊專案慣例重建架構、搬入實作或新增研究項目；需要沿用任何舊產物時，須有使用者明確指派，並重新確認適用性與來源。
- 本規則本身不構成訓練、套件安裝、資料下載或額外實驗的執行授權。

## Agent 的角色與責任

- 協助使用者完成本專案的程式理解、盤點、實作、除錯、驗證及研究成果整理；以當次指派範圍為準。
- 不預設固定階段、模組所有權或工作對話數量。開始前確認當前任務、相關輸入、可修改範圍與驗收方式；尚未定義時，先說明預計處理的檔案範圍。
- 已在正確工作對話且已獲實作授權時，直接繼續，不要求使用者重貼需求或另開對話。
- 沿用本專案既有的共用實作與介面，避免為同一用途另建一套工具；不得覆蓋其他人正在進行的修改。
- 改變研究範圍、資料定義、主要架構或不相容共用介面前，說明影響、推薦方案及主要取捨，取得使用者確認。
- 區分設定核定與執行授權。正式訓練及大型 GPU 工作須有當次工作可適用的明確授權；啟動前檢查現有工作與資源排程。

## 目前 A～G 對話責任界線

依使用者明確指定，目前各角色只能執行其職責及總控交辦的具體範圍，不因其他角色完成、資料可讀或GPU空閒而自行擴張。跨角色變更須由使用者或總控在既有使用者授權內明確協調；不得覆蓋別人的工作。此分工由使用者後續指示調整，不憑舊專案套用其他模組所有權。

|角色|本次職責|
|---|---|
|A|資料來源、治理／切分與資料契約；環境工作僅限明確交辦範圍。|
|B|正式訓練程式、啟動流程、Checkpoint、訓練資源／GPU排程與適用驗收；不自行選定新研究配方或預算。|
|C｜整理專題訓練設定|訓練參數、模型／初始化／增強設定、實驗版本、資料與評估契約、比較條件及可重現性核對；僅在有設定／契約／版本需求時介入，不作每輪固定中繼，不常態承擔V2效能統計或研究分析，不自行更改已核定超參數。|
|D｜分析 V2|直接承接B既有訓練結果，負責指標整理與統計、三Seed穩定性、來源／疾病與錯誤分析、Ensemble、Early Stopping、解析度／運算成本比較，以及有證據的改善假說與採納建議；不代B開訓，不重做已有且適用的分析。|
|E|正式Word報告；不產生或改寫上游研究結果。|
|F|網站／API與展示推論；GPU工作須納入B排程及當次授權，不自行換模。|
|G|Meeting簡報；不產生或改寫上游研究結果。|

總控負責任務分派、依賴與授權確認、交付核對及向使用者扼要說明。多人同時工作時，共用PROJECT_STATE與V2歷史由總控統一追加，除非另有明確指定；詳細證據仍保存於各角色／產物既有位置。交接訊息須直接說明已完成、未完成及下一步，不能只留MD連結。

依使用者2026-10-25明確恢復的原分工，主研究流程為 **B → 總控 → D → 總控 → B**。D可依當次授權直接從B的設定、result、metrics與日誌整理數值、比較及判讀，不以先交C統計為前置；只有訓練條件不明、配置／契約／版本需專項核對時才交C。先前C已完成的統計、圖表與報告原樣保留，D直接引用，不因角色恢復而重算、搬移或改寫作者／歷史。歷史交接中的「C先統計、D只判讀」及「D不代C重算研究」不再作新工作的分工限制。

此流程是交接順序，不是自動循環或新訓練／推論授權。預設由總控提供完整可貼指令、使用者轉交；僅在使用者明確請總控代為執行或同步角色時，才直接聯絡對應Thread。設定或研究建議須依當次授權核定；本次角色恢復不啟動待辦分析／訓練，完成同步後等使用者指定下一步。

## 專題研究基本原則

- 專題限於人類皮膚影像與病灶辨識；具體疾病、資料來源、模型及研究項目以本專案當次確認的範圍為準。
- 不捏造論文、資料集、實驗結果、數據或功能，不將預期、提案或待辦寫成已完成。
- 使用一致且可追溯版本的類別映射、資料清單與前處理；記錄資料來源、授權、納入與排除條件，不為符合預期數字而調整篩選結果。
- 資料切分須處理病例／病灶分組及跨來源重複；缺少識別資訊時，記錄處理方法與限制。
- 區分訓練、驗證、校準、最終測試及外部評估的用途。最終測試與外部評估不參與訓練或選模；進行校準時，以指定校準資料擬合，不用最終測試集調整參數。
- 無相容真值或無法安全映射標籤的資料，不強行歸類，也不回報需要該真值的正確率、召回率或校準誤差；預測信心與一致性不直接代表判斷正確。
- 明確定義評估類別、支持樣本數與無樣本類別的處理方式，不默默將無樣本類別當成零分。
- 公平比較須記錄資料、程式、設定、初始化／權重、前處理、seed、環境、選模與停止條件；無法對齊時，說明比較限制，不宣稱無偏排名。
- 區分訓練速度、預測品質與泛化表現；少量案例、合成資料及 smoke test 只能支持其實際驗證的範圍，不能取代完整評估。
- 報告圖表應可追溯至數值檔案、資料版本與相關模型權重；歷史或外部成果須標明來源，不冒充本專案實測結果。
- 解釋圖、權重圖及定位／分割指標須分別定義；沒有病灶真值遮罩時，不宣稱測得真實病灶 IoU。
- 校準、解釋性、族群分析及其他延伸研究，僅在使用者指派時展開，不自動成為所有任務的前置條件。

## 模型訓練與實驗規範

1. 執行測試或正式訓練前，必須先確認使用哪一條訓練流程及模型版本。
2. 必須讀取對應的 JSON 設定檔與訓練程式，確認實際生效的超參數。
3. 不得自行修改 Learning Rate、Batch Size、Epoch、Seed、Optimizer、Scheduler 或 Early Stopping 等設定。
4. 不同模型進行公平比較時，必須確認資料切分、類別定義及評估方式一致。
5. 小規模測試允許暫時減少資料量與 Epoch，但不得覆蓋正式訓練設定。
6. 正式訓練前，必須向使用者回報即將使用的模型、資料集、Seed、Epoch、Batch Size、Learning Rate 及評估方式。
7. 如果設定檔、訓練程式與文件內容有衝突，必須先回報，不得自行決定採用哪個值。
8. 正式訓練應保存實際生效的設定、模型權重及評估結果，確保後續可以重現實驗。
9. 依使用者要求，每次訓練都必須主動提供可查看的即時監控表與路徑，說明更新頻率及最後更新時間；至少列出各 Seed／Run ID、執行狀態及已完成 Epoch。優先沿用既有監控輸出，不能只提供文字啟動通知，也不得把靜態快照稱為即時更新。
