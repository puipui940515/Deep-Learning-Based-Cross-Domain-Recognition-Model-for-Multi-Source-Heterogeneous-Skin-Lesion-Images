本資料夾保存專案的階段性匯總節點。每個節點代表當時已完成工作、有效實驗結論、已知限制與下一步工作的固定快照。

## 本資料夾的檔案

| 檔案 | 性質 | 可否手改 |
|---|---|---|
| `時間軸.md` / `timeline.json` | **專案事件時間的唯一權威來源** | 否，改 `build_timeline.py` 後重新產生 |
| `格式約定.md` | 全專案索引與 README 的共同格式 | 是 |
| `checkpoints.json` | 匯總節點與修正紀錄的機器可讀索引 | 是 |
| `節點NN_*.md` | 凍結快照 | 否，只能在「後續修正」區追加 |
| `CP-NNN_執行計畫_*.md` | 活文件 | 是，須在「修訂紀錄」留列 |
| `build_timeline.py` | 時間軸產生器 | 是 |
| `check_consistency.py` | 索引漂移檢查（唯讀） | 是 |
| `apply_status_blocks.py` | 為實驗 README 產生標準狀態區 | 是 |

例行檢查：

```powershell
python "開發歷程/build_timeline.py"
python "開發歷程/check_consistency.py"
```

## 節點規則

1. 節點使用兩位數流水號：`節點01`、`節點02`……。
2. 新節點只記錄相對前一節點的增量與重新判定，不回頭覆蓋舊節點的歷史結論。
3. 若舊節點有事實錯誤，只能在該文件的「後續修正」區留下更正日期與原因。
4. 實驗結果必須連回原始 JSON、CSV、checkpoint 或驗證報告，不能只留下口頭結論。
5. `checkpoints.json` 是機器可讀索引；Markdown 文件是主要的人類可讀紀錄。
