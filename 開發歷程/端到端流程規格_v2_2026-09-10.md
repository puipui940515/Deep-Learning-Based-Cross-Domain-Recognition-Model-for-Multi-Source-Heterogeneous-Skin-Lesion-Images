# 端到端流程規格 v2（ROI 導向）

建立日期：2026-09-10　狀態：`未開始`　適用線：論文線  
目的：定義「一張影像進來，到一組輸出出去」之間的每一個步驟，作為全專案唯一的流程權威。  
流程圖：`開發歷程/端到端流程圖_v2_2026-09-10.mermaid`（原始檔，與本文件同步維護）、同名 `.svg`／`.png`（由原始檔產生，勿手動編輯）。

> **為什麼需要這份文件**：2026-09-10 盤點發現專案內同時存在四條前處理路徑（第二階段、資料治理、基底模型發展、UI 推論），彼此在幾何處理與正規化上互不相同，且沒有任何一份文件能回答「一張圖進來會發生什麼」。論文方法章需要這個答案。

## 0. v1（現況）與 v2（本規格）的差異總表

| 階段 | v1 現況 | v2 本規格 | 理由 |
|---|---|---|---|
| 影像解碼 | `Image.open` → `convert("RGB")` | 加 `exif_transpose` | PAD 與 SCIN 是手機照，帶方位旗標 |
| 幾何 | 三種：正方形擠壓／保長寬比 edge 補邊／擠壓 | **統一為 ROI 中心正方形裁切** | 現況本身即為 source 指紋 |
| ROI | 欄位已定義但 `enabled: false` | **離線算好寫入 manifest** | 可重現、可版本控制、訓練期零成本 |
| 正規化 | `[0.5]` 與 ImageNet 混用；UI 預設 `[0.5]` | 全線 ImageNet，**且為必填** | 消除靜默失配 |
| 增強 | 三套，強度不一 | 統一；**降低隨機裁切幅度** | 避免與 Stage 2 職責重疊 |
| 校準 | 已算出但未接上（T=0.8569） | 接上，且改用獨立 split | 目前 UI 輸出原始 softmax |
| 輸出 | 七類 top-1 + 原始機率 | 校準機率＋良惡聚合＋拒答＋ROI 座標 | 72% BA 的模型不該只回一個 99% |
| 熱力圖 | 畫在裁切座標系 | 反投影回原圖座標 | 有 ROI 後才可逆 |

## 1. Stage 0　影像入口

**輸入**：任意 JPG／PNG／TIFF  
**處理**：

1. `Image.open` → `ImageOps.exif_transpose` → `convert("RGB")`
2. 記錄 `orig_width`、`orig_height`、`orig_aspect_ratio`、`file_format`

**輸出**：RGB 影像 + 原始尺寸中繼資料

**為什麼**：目前全線都沒有 `exif_transpose`。皮膚鏡影像不受影響，但 PAD-UFES-20 與 SCIN 是手機拍攝，帶方位旗標的影像會被以錯誤方向送進模型。訓練期的旋轉增強會掩蓋這個問題，推論期則不會。

**論文用途**：無，屬工程正確性。

---

## 2. Stage 1　ROI 決定（離線，一次性）

這是本規格的核心。**ROI 不在訓練期即時計算**，而是離線算好、寫進 manifest、納入資料契約。

### 2.1 兩個 ROI 產生器

| 代號 | 方法 | 需要標註 | 角色 |
|---|---|---|---|
| **R-A** | 傳統影像處理 | 否 | baseline，方法章可完整描述 |
| **R-B** | 小型 U-Net | 是（用公開分割子集） | 主方法 |

**R-A 步驟**：短邊縮到 512 → 形態學 blackhat 偵測毛髮並修補 → 取藍通道（病灶在藍通道對比最強）→ Otsu 門檻 → 開閉運算 → 取最大連通區域 → 排除觸邊比例過高者（皮膚鏡暗角）→ 外接矩形。

**R-B 步驟**：ISIC 2017／2018 Task 1 提供數千張病灶分割 mask，公開可取得，與本專案影像同 domain。以此訓練一個輸入 256×256 的小型 U-Net，推論至全部影像，取前景機率圖 → 門檻 → 最大連通區域 → 外接矩形。

> **洩漏風險，務必處理**：R-B 的訓練影像若與本專案的訓練／驗證影像重疊，等於讓 ROI 產生器「看過」評估資料。必須先以 `isic_id` 對 `unified_manifest_v1.csv` 做去重，重疊者排除出 U-Net 訓練集。`驗證/run_all.py` 已有 isic_id 層級比對能力，直接沿用。

### 2.2 寫入 manifest 的欄位

| 欄位 | 型別 | 說明 |
|---|---|---|
| `roi_source` | `none` / `classical` / `unet` | 哪個產生器 |
| `roi_xmin`、`roi_ymin`、`roi_xmax`、`roi_ymax` | float 0–1 | normalized xyxy，與現有 config 的 `coordinate_format` 一致 |
| `roi_area_fraction` | float 0–1 | ROI 面積佔原圖比例 |
| `roi_quality` | float 0–1 | 產生器自評（R-A 用形狀規則性；R-B 用前景機率均值） |
| `roi_fallback` | bool | 品質不足而退回全圖 |
| `roi_component_count` | int | 連通區域數，供 Stage 10 使用 |

`roi_quality` 低於門檻時，ROI 設為全圖並標記 `roi_fallback = true`。

**逐來源的 fallback 率必須報告。** 若 R-B 在皮膚鏡上 fallback 2%、在 PAD 上 fallback 30%，那就是把一種 source 偏差換成另一種，這必須寫進限制章而不是藏起來。

### 2.3 治理

新增欄位使資料契約升版至 `skindetect-data-contract-v1.1`，須通過既有的治理閘門與 `check_consistency.py`。ROI 產生的時間、產生器版本、參數雜湊寫入 `reports/05_roi_generation.json`。

## 3. Stage 2　裁切與幾何統一

**這一步是移除 source 捷徑的實際機制，不是 Stage 1。**

1. 取 ROI 中心 $(c_x, c_y)$，邊長 $L = \max(w_{roi}, h_{roi}) \times M$
2. 以 $(c_x, c_y)$ 為中心取 $L \times L$ 的**正方形**視窗
3. 超出原圖邊界處以 `edge` 補邊（與現行 `pad_mode` 一致）
4. Resize 至 $S \times S$

### 為什麼一定要是正方形

若沿用 ROI 本身的長寬比再擠壓成正方形，各來源的長寬比差異會再次變成幾何指紋 —— 也就是現況的問題原封不動地被搬到裁切後。**取正方形視窗才真正切斷這條路徑**：無論原圖是 4:3 還是 1:1，送進模型的都是「病灶置中、佔畫面固定比例」的正方形。

### margin $M$ 是本輪唯一的實驗變因

| 設定 | $M$ | 意義 |
|---|---|---|
| `full` | ∞（全圖） | 對照組，等同 v1 |
| `tight` | 1.0 | source 訊號最少，上下文最少 |
| `medium` | 1.3 | |
| `loose` | 1.6 | 保留較多病灶周邊皮膚 |

病灶周邊皮膚**有診斷意義**（病灶與周邊的對比、周圍紅斑、相對大小），不是雜訊。$M$ 量化的正是「移除 source 訊號」與「保留臨床上下文」之間的取捨。

$S$：探索期 224，確認期 384。

## 4. Stage 3　正規化

全線改用 ImageNet mean／std，廢除 `[0.5]`。

**同時修掉一個靜默陷阱**：`ui_prototype/model_runtime.py` 目前是

```
mean = normalization.get("mean", [0.5, 0.5, 0.5])
```

registry 漏填 `normalization` 時會安靜地套用錯誤統計，不報錯、不當掉，只是變差。應改為**必填，缺少即拒絕載入**。

---

## 5. Stage 4　增強（僅訓練期）

沿用 `基底模型發展_可切換正式訓練` 那套（已相當完整），但有一處必須調整：

| 項目 | v1 | v2 | 理由 |
|---|---|---|---|
| 隨機裁切 | `RandomResizedCrop(scale=0.70–1.0, ratio=0.75–1.33)` | 小幅 jitter：scale 0.90–1.10、translate 0.05 | 病灶已由 Stage 2 置中，大幅隨機裁切會把它裁掉或再次引入長寬比變異 |
| 其餘 | 翻轉、旋轉 20°、ColorJitter、blur、grayscale、autocontrast、高斯雜訊、RandomErasing、mixup 0.2 | 不變 | — |

這是真實的職責衝突：v1 的強隨機裁切部分扮演了「讓模型學會在任意位置找病灶」的角色；v2 把這個工作交給 Stage 2 後，就不該再重複，否則兩者互相抵銷。

---

## 6. Stage 5　模型

**本輪不動架構。** 只改前處理才能歸因；同時改模型會重蹈 v13 一次改八個因子的覆轍。

- 架構：ConvNeXt-Tiny（主）、ResNet18（對照）
- 初始化：ImageNet
- GRL、site auxiliary、explicit features：維持現有 config 不變

> **附帶的驗證機會**：若裁切確實移除了 source 訊號，GRL 的邊際效益應該下降。「加了 ROI 之後 GRL 變得可有可無」本身就是假設成立的第二個證據，值得單獨做一組 GRL on／off 對照。

---

## 7. Stage 6　訓練期選模

選模指標維持 `0.5 × mean_source_BA + 0.5 × worst_source_BA` 不變。

**新增監控（只記錄，不進 loss）**：每個 epoch 在驗證集上訓練一個線性 source probe，記錄其準確率。這是本輪的主要證據來源，理由見第 9 節。

---

## 8. Stage 7　訓練後處理

1. **溫度校準** —— 沿用現有實作（`scripts/postprocess.py`）。
2. **校準集必須獨立**：現況 `calibration.json` 的 `validation_samples: 3614` 用的是 validation，而 validation 同時用於選模，存在輕微樂觀偏差。應自訓練集切出獨立 calibration split，或採 cross-fitting。這是審查會問的問題。
3. **拒答門檻 $\tau$** —— 在 calibration split 上畫 risk–coverage 曲線，選在指定覆蓋率下風險最低的點。**不是拍腦袋定的**。
4. 輸出 `calibration.json`：$T$、ECE before／after、$\tau$、使用的 split 名稱、`test_used: false`。

---

## 9. Stage 8　推論輸出

```
logits → ÷ T → softmax → 七類機率
```

回傳結構：

| 欄位 | 說明 |
|---|---|
| `probabilities` | 七類校準後機率 |
| `top1` | 最高類別 |
| `binary` | 良性 {NV, BKL, DF, VASC} vs 惡性／癌前 {MEL, BCC, AKIEC} 的聚合機率 |
| `abstain` | `max_prob < τ` 時為 true，前端顯示「不確定」 |
| `roi` | 使用的 ROI 座標（原圖座標系） |
| `roi_fallback` | ROI 是否退回全圖 |
| `calibration` | 使用的 $T$ 與來源檔 |

**良惡二分不是附加功能，而是因為它的統計基礎更穩。** DF 在驗證集只有 18 張，七分類 top-1 在稀有類別上本來就撐不住；二分類的 recall 撐得住，而且「這個要不要看醫生」才是使用情境真正的問題。

---

## 10. Stage 9　可解釋

Grad-CAM 在裁切後的座標系計算，再**反投影回原圖座標**。因為 Stage 2 的變換（中心、邊長、補邊量、縮放比）全部已知且可逆，這個反投影是精確的。

現況 `heatmap_audit/summary.json` 的 `flip_hot_iou = 0.524` —— 左右翻轉後熱區只剩約一半重疊 —— 應在 ROI 導入後重測。若模型真的被逼回病灶，這個數字應該上升。這是假設成立的第三個證據。

---

## 11. Stage 10　多病灶（延伸，質性）

當 `roi_component_count > 1` 且各連通區域品質皆達標時，對每個區域各跑一次 Stage 2–8，輸出多組 `(bbox, 類別, 機率)`。

> **本情境無法量化評估。** HAM10000、BCN20000、ISIC、PAD-UFES-20 全部是「一張圖 = 一個病灶 = 一個標籤」，沒有多病灶的 ground truth，因此無法計算 precision／recall／mAP。論文中只能作為質性示例，並明確標注未量化評估。
>
> 若日後要取得真實數字，唯一的路是引入本身即帶 bounding box 的多病灶資料集（如 iToBoS 2024）；退而求其次可建構合成多病灶基準（將已知病灶貼至乾淨皮膚背景，ground truth 由建構方式決定），但必須寫明是合成的。

## 12. 量測計畫

### 主要證據：source probe 準確率

跨來源 BA 的雜訊地板是 **2s = 3.88pp**。裁切對皮膚鏡影像的效果幾乎不可能達到 4pp，因此若只看 BA，很可能得到「無法區分」而誤判裁切無效。

| 指標 | 現況 | 假設成立時 | 解析度 |
|---|---|---|---|
| **source probe 準確率** | 86–96% | 顯著下降 | 高，單 seed 可見 |
| worst-source BA（BCN） | — | 可能不動 | 低，需三 seed |
| mean BA | 70.78% | 可能不動 | 低，需三 seed |
| `flip_hot_iou` | 0.524 | 上升 | 中，10 張樣本太少，應擴到 100 張 |
| ROI fallback 率（逐來源） | — | 應 < 10% 且各來源接近 | 高 |

**先用便宜的 probe 驗證機制，成立後再花三 seed 量 BA。順序反過來會浪費算力。**

### 誠實的預期

我預期 mean BA 與 worst-source BA **不會有可辨識的變化**。最差來源是 BCN（皮膚鏡，病灶本就佔滿畫面，裁切拿不掉多少東西），而裁切幫助最大的是 PAD（手機臨床照）—— 但 PAD 目前表現本來就好。

因此本輪的論文價值在於**機制證據**（source 訊號被移除、模型注意力被逼回病灶），而不是準確率數字。若最後 probe 也沒掉，那就是一個乾淨的負面結果，同樣值得寫進節點。

## 14. 風險與限制

| 風險 | 說明 | 處置 |
|---|---|---|
| 分割器逐來源品質不均 | 皮膚鏡準、手機照不準，等於換一種 source 偏差 | 逐來源報告 fallback 率與 `roi_area_fraction` 分布 |
| ROI 洩漏 | R-B 的訓練影像與本專案評估影像重疊 | 以 `isic_id` 去重，沿用 `驗證/run_all.py` |
| 丟失臨床上下文 | 緊裁切移除周邊皮膚等真實訊號 | margin sweep 量化取捨 |
| 增強與裁切職責重疊 | 強隨機裁切抵銷 Stage 2 | 降低 scale 範圍至 0.90–1.10 |
| 校準集不獨立 | validation 同時用於選模與校準 | 切出獨立 calibration split |
| 多病灶無法評估 | 無 ground truth | 只作質性示例，明確標注 |
